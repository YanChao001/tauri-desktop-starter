## 维护规则

### 一份事实只写一处

| 文档位置                                                 | 唯一维护的内容                                                 |
| -------------------------------------------------------- | -------------------------------------------------------------- |
| 根 README / 英文 README、CONTRIBUTING、AGENTS            | 介绍、启动与工作入口；详细规则通过链接按需读取                 |
| 本索引                                                   | 任务导航、文档职责与维护方式                                   |
| `architecture.md` 与领域指南                             | 当前职责、数据归属和契约；扩展、虚拟会话等领域细则留在各自指南 |
| 开发 / 测试 / 发布 / 排障指南                            | 可执行步骤、检查选择、分发与恢复操作                           |
| `conventions/`、`security.md`、`engineering-at-scale.md` | 编码与界面约定、安全边界、实质设计取舍的处理方式               |
| `docs/plans/`、`docs/adr/`                               | 仍需维护的跨里程碑计划、长期决策的原因与历史                   |
| issue / PR / Release                                     | 一次变更的范围、评审、实际验证与交付证据                       |

写入前搜索已有定义，更新职责最明确的位置，其余引用该位置。按不同任务或读者拆分文档；现有章节能承载时就地维护。合并或删除内容时修复入链，ADR 按 [状态规则](./adr/README.md#命名与状态) 保留历史。计划落地后将当前规则收敛到对应指南，不把计划用作第二份现状说明。

### 内容与验证

- 自有工程文档使用中文、UTF-8、可读链接文字和存在的文件 / 标题锚点；代码块标明语言，避免混用各 shell 的语法。
- 说明职责、边界、操作与原因。版本、脚本完整清单和默认配置优先链接源码；示例保留完成任务所需的最短步骤。协议限额、权限与兼容规则集中在对应指南，区分当前实现、历史决定和可选后续。
- 代码与相关文档同改。设计提案与当前实现分开，不把 CI 配置、demo 数据或未执行的目标平台检查写成实测结果。
- 文档改动检查受影响文件的格式、本地文件 / 标题链接和事实；命令、默认值与权限说明对照实现。修改标题时同步修复引用，跨仓库固定版本材料链接到相应版本。执行范围按 [日常验证](./testing.md#日常验证范围) 选择。
- 提交历史由 Git 维护，不另建 CHANGELOG 或临时审查流水账；发布说明补充用户可感知的变化、升级要求和已知限制。

代码去重与抽象见 [代码风格](./conventions/code-style.md#重复与抽象)；规模化维护职责见 [文档层级](./engineering-at-scale.md#文档层级与维护职责)。
