# 设备工作台基座实施计划

- 状态：M0–M4 首批已实施并完成本机无头验证；M5–M7 尚未实施，按各自设计与验收继续推进。
- 范围：从当前桌面 demo 演进为可组合的桌面助手基座，先建立设备会话、原始记录与回放的无头闭环。
- 关联：[架构决策](../adr/0024-device-session-capture-boundaries.md)、[架构说明](../architecture.md)、[扩展指南](../extensions.md)。
- 决策与评审：维护者明确授权按里程碑实施并允许重构；保留实现自审和独立交叉检查，不虚构第二位人类审批人。

## 问题与验收目标

现有插件以命令、视图和短时 Wasm 调用为中心，能够支撑独立小应用，但设备连接、多视图共享、连续记录与解析状态需要单独的业务身份和生命周期。增加插件数量、放宽超时或保持隐藏 iframe 不能解决这些问题。

首批必须提供可以运行和验证的能力，不只创建接口：

1. 同一虚拟设备会话允许多个独立读取游标；慢读取者不阻塞生产，超出保留窗口报告明确缺口。
2. 连接重建产生新代次，旧生产／发送句柄失效；关闭显示不等于关闭会话。
3. 写入按会话统一排序；连接中断不自动重发旧队列。虚拟写入回执不得冒充真实设备确认。
4. 字节保持二进制，可记录和只读回放；文件校验、资源上限和未来版本保护不依赖界面。
5. CLI 使用同一套模块完成虚拟采集、记录和回放，不初始化 Tauri、网络、串口或 GUI，不覆盖已有输出。
6. 修复已有停止请求保留容量未贯穿窗口准入的问题，保留身份、授权、维护和窗口代次校验。

首批不承诺真实串口、硬实时、任意负载无损、应用退出期间持续采集、插件可下载原生服务或全面历史版本兼容。

## 模块划分与依赖

| 模块                               | 责任与数据归属                                                       | 不承担的责任                                                              |
| ---------------------------------- | -------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| 通用宿主与现有扩展                 | 安装信任、授权、Wasm worker、隔离 HTML、窗口、恢复、插件私有数据     | 不把串口业务加入所有插件的强制依赖，不开放任意 IPC                        |
| `src-tauri/src/device/`            | 会话与连接身份、字节事件、有限保留与独立游标、虚拟输入和有界发送仲裁 | 不读写文件、不依赖 Tauri／React、不实现物理串口，不替调用边界决定用户授权 |
| `src-tauri/src/capture/`           | 版本化记录文件、完整性与额度校验、只读回放、截断／损坏状态           | 不连接设备、不发送数据、不自动修复或覆盖原始记录                          |
| `src-tauri/src/bin/device_tool.rs` | 组合虚拟会话与记录回放，提供可操作无头开发入口                       | 不初始化桌面、不访问用户应用数据、不提供任意设备路径执行能力              |
| 未来串口适配                       | 平台枚举、独占打开、控制线、配置和真实读写，映射为设备模块事件       | 不在读取环中运行第三方逻辑，不承诺驱动未提供的时序和硬件能力              |
| 未来工作台与扩展贡献               | 设备树、终端、HEX、字段、图表及有限 provider／视图注册               | 不持有唯一原生连接，不用页面保留维持后台采集                              |

依赖方向为 `device-tool → capture → device 公共事件模型`，以及 `device-tool → device`。设备模块不反向依赖记录实现。新增的公共类型只供 Rust 模块和 CLI 使用；首批不新增 IPC 或插件权限，不能把内部 API 作为授权边界。

先在当前 Rust crate 内保持模块化，不引入 workspace、通用插件总线、空 provider registry 或新的运行时依赖。达到独立交付、平台 SDK 隔离或无桌面编译的真实需求时，再拆 crate／进程。

## 契约与失败路径

### 身份与状态

会话身份、连接代次和读取游标分开。游标引用同一会话历史，连接代次用于拒绝旧连接操作；重新连接后不重置成可被旧游标误认的新历史。不同会话不能互用句柄。普通视图的挂载／卸载不在设备模块内触发连接状态改变。

事件至少区分连接状态、接收／虚拟发送字节和缺口；字节事件带序号、方向、连接代次、主机观察的单调时间及字节偏移。时间戳不能表述为逐字节线路时间。输入和状态变更先校验再提交，失败不推进序号、不丢弃原事件。

发送队列与控制路径分开；停止、关闭和断连不依赖普通队列腾出位置。旧代次排队写入在连接变化时失效。虚拟传输只提供本地模拟结果，不能产生“设备 ACK”或真实串口成功记录。

### 数据与容量

内存历史、单次字节块、读取批次、发送队列与记录帧均有独立上限。读取者落后时报告被淘汰的序号区间；未知的驱动丢失数量不能伪造为精确数。首批拉取游标协议用于验证有界数据语义，不宣称已经实现 Channel、后台推送或物理流控。

文件使用版本化二进制帧，元数据与原始字节分离，逐帧校验。回放按帧读取，不把整个日志塞入 JSON／base64。严格读取拒绝未知版本和损坏；显式恢复预览可以返回已验证前缀与截断位置，但不修改原件、不静默把坏记录判定为完整记录。

创建输出使用排他创建语义，既有文件不覆盖。记录失败停止继续追加并保留可诊断结果；完整结束标记与未完成尾段必须可区分。具体格式与当前额度在模块操作指南形成后统一维护，计划不重复长期规范。

### 权限与生命周期

首批只有显式 CLI 输入／输出和内存虚拟设备，不注册桌面状态、IPC 或自动后台线程。未来接入前，须补齐资源句柄授权、窗口与 session 所有权、撤权、退出协商和数据目录恢复设计，不能直接把这些 Rust 内部方法开放给插件。

原生 provider 属于不同信任等级；今后独立分发仍须签名、平台目标、协议握手、监督和停机更新。同用户进程不是天然 OS 沙箱，插件签名也不证明固件适配设备。

## 后续里程碑的实施入口

以下是依赖明确的后续任务，不是已建模块、稳定 API 或预先批准的权限。进入该里程碑时，结合首批结果补数字预算与平台验收对象；有实际契约变化再写对应 ADR。

### M5 原生会话与真实串口

1. **M5a 资源与权限**：定义设备枚举结果、选择授权、会话所有者和读／写／配置／刷写的风险分组；设备路径只在可信适配层使用。列出显示关闭、后台继续、明确停止、退出、更新、撤权的状态机。
2. **M5b 平台适配**：评审串口依赖的维护、许可证、体积和 OS／驱动能力；实现唯一底层连接、有限接收、参数与写入仲裁。能力结果区分支持／不支持／未知，连接重建不复用旧请求。
3. **M5c 原生边界**：经统一命令注册、生成绑定和门面开放最小控制面；二进制数据通过有界批次通道，定义订阅进度、淘汰缺口、取消与资源释放，不用无限广播事件替代数据面。
4. **M5d 生命周期与记录**：在真实退出／更新／撤权流程中停止准入、使未执行请求失效、等待 I/O 与文件完成；若无法确认设备结果，保留部分完成／未知状态。恢复工程只恢复配置，不自动启动发送。

并行边界为平台适配、资源／会话政策、前端门面与测试 fixture；共享 DTO、绑定、Cargo、生命周期入口由集成方维护。先跑虚拟后端故障注入，再验目标设备的占用、拔插、休眠、DTR／RTS、非标准参数和取消；浏览器替身不充当硬件证据。

### M6 可组合工作台与业务插件

1. **M6a 工作区与多显示**：把 `workspaceId`、`sessionId`、`surfaceId` 分开；终端／HEX 使用同一会话，弹出窗口不重开端口。工程保存声明式配置、布局和版本，不保存秘密、原生句柄或可恢复危险授权。
2. **M6b 有限贡献点**：用设备树、帧表、字段检查器和状态项验证视图／菜单／设置契约；动作复用命令注册。上下文控制呈现，最终授权仍在原生，不把不可信 React 注入宿主。
3. **M6c 协议与数据来源**：先接一个真实协议的分帧／解码插件与派生视图，保留 raw 范围引用；验证任意分块、缺口重同步、重连、回放 seek 和代码升级后的状态重建。显式状态可用时不立即新增持久 Wasm actor。
4. **M6d 工程与插件失效**：提供者停用前消费者收敛，登记返回可回收句柄；缺失／禁用插件保留工程占位和配置，业务 schema 迁移失败保留副本。插件互调不自动转授提供者权限。

并行边界为终端／HEX、工作区模型、一个协议插件及贡献注册；共享会话模型与 SDK 契约先固定。界面验收默认无头，iframe 焦点／快捷键、输入法、停靠重建和真实多窗口按独立平台验收处理。

### M7 按需交付与作者工具链

1. **M7a 测量与选择**：分别测基础安装包、可选包、缓存、录制文件、冷暖激活与内存；按成本和使用率选择真正移出基础交付的依赖，不用禁用开关冒充瘦身。
2. **M7b 可选原生包**：仅为已选定的厂商 SDK／烧录器定义平台目标、签名、完整哈希、可信启动、协议握手、健康与停止；停机升级须处理旧进程、原地失败和人工恢复，不加载不可信动态库进宿主。
3. **M7c 公共 SDK／CLI**：提取已证明需要独立发布的契约与校验组件，提供模板、预编译工具和回放 fixture；Rust 继续是类型来源。区分包格式、服务版本、已安装、可用和已授权，兼容窗口只覆盖明确支持的版本。
4. **M7d 渠道和套装**：存在需求后增加签名私有／离线渠道、发布者身份及密钥轮换；功能套装只是推荐安装，不能替代依赖与授权。换来源承接旧数据单独确认，代码回退不自动回退业务数据。

在这些需求形成之前，不创建空 provider registry、完整依赖求解器、额外守护进程或新包格式。正式安装版、目标平台和硬件的证据仍独立保留，不由 CI 配置替代。

## 并行开发与 Git

从 `develop` 创建 `feature/device-workbench-foundation`。并行工作使用隔离 worktree，核对实际 HEAD 与设计基线；自动创建停留旧提交时只读获取已提交 M0 文档，不擅自改写分支。按独占文件范围分工：设备、记录、现有控制修复不互写文件；`lib.rs`、Cargo、绑定、操作文档和 CI 由集成方维护。

依赖的公共事件契约先确定，再并行写实现。子工作区不提交、推送、重写分支或运行竞争的全量 Cargo 构建；集成方审阅最终补丁后按 M1、M2、M3、M4 顺序提交，保持特性分支历史线性。已提交里程碑不为美化历史反复改写；同步上游仍按 [Git 协作规范](../conventions/git-workflow.md) rebase，保护分支只通过 PR 合入。

不直接修改或提交市场子模块。没有用户进一步授权时不推送、不创建远程发布、不合入保护分支。

## 验证与发布边界

- 文档：局部 Prettier、本地文件与标题链接；计划与当前实现明确分开。
- Rust：先准备 `dist/`，集中运行格式、相关测试、CLI 集成和 clippy；共享 target 的 Cargo 命令顺序执行。
- 工程：新增 CLI 同步初始化、构建和 CI 中实际受影响的规则，保留锁文件，不借机升级依赖。
- IPC：首批无新增命令或导出 DTO；仍检查生成绑定无漂移。后续增加命令时运行生成与检查并提交结果。
- 桌面：不启动 GUI、不运行交互 E2E、不操作真实串口；硬件、正式安装版和其他平台必须单独记录未验范围。
- 性能：先验证有界资源和正确性，不把测试吞吐写成正式设备保证；在 M5 对目标硬件制定数字预算并实测。

## 复查与后续细化

若当前 crate 链接成本阻碍无头工具开发、虚拟／真实源不能共用事件模型、单维护者难以承担多层协议，先缩小接口或拆出纯领域 crate，不用扩大通用 registry 掩盖职责问题。只有真实组合需求出现时才引入插件依赖求解、持久 Wasm actor、停靠布局或可下载原生执行器。
