# 虚拟数据流与记录回放示例实施计划

- 状态：M0–M4 基础示例已实施；M5–M7 尚未实施，仅在出现实际需求时评估。
- 当前操作与契约：[虚拟会话指南](../device-workbench.md)；长期取舍：[ADR 0024](../adr/0024-device-session-capture-boundaries.md)。

## 问题与验收目标

现有插件以命令、视图和短时 Wasm 调用为中心。基础示例验证连续字节流可以由独立于页面的会话持有，多个读取者共享有限历史，并通过无头 CLI 完成虚拟采集、二进制记录与只读回放。

基础目标已落实：读取者相互独立，慢读取者收到明确缺口；重连拒绝旧连接操作，不重发旧队列；记录保留原始字节，损坏与未完成状态可区分。当前范围是内存虚拟会话和显式文件参数，不包含外部资源接入、桌面流式 IPC 或退出后持续采集。

## 模块划分与依赖

`device/` 管理会话、有限历史与虚拟发送，`capture/` 消费设备公共值类型，`device-tool` 组合两者；设备不反向依赖记录或页面。源码入口与当前职责见 [模块与责任](../device-workbench.md#模块与责任)。

模块仍位于当前 Rust crate。只有独立交付、平台 SDK 隔离或无桌面依赖编译的需求出现时，再评估拆 crate 或进程。

## 契约与失败路径

### 身份与状态

会话、连接代次与只读游标分别管理；显示生命周期不改变会话。当前发送结果和关闭结算语义见 [会话、连接与显示](../device-workbench.md#会话连接与显示)。

### 数据与容量

有限历史、读取批次和发送队列的行为见 [有限历史与批次](../device-workbench.md#有限历史与批次)；二进制文件的校验、严格读取与显式前缀恢复见 [记录格式与失败边界](../device-workbench.md#记录格式与失败边界)。这些当前契约由指南维护，计划不另存一份。

### 权限与生命周期

内部 Rust 句柄只表达会话身份。若开放给前端或插件，应按实际入口设计资源选择、授权、所有者、撤权与退出行为，见 [安全边界](../security.md#虚拟会话内部接口)。

## 可选扩展方向

M5–M7 是需求评估入口，不是已确定路线、稳定 API 或待补齐的基础能力。需要其中某项时，再确定最小交付与对应验收；可以独立选择，不必按编号全部实施。

### M5 原生服务接入示例

**触发条件**：demo 或派生项目选定了真实数据来源，需要从桌面界面操作。

围绕该来源接入最小适配与控制面，复用当前会话和记录模型；授权及生命周期按实际操作风险设计，IPC 遵循既有生成绑定和原生门面。验收来源中断、重连、写入结果、撤权和退出时的资源释放；仅对新增边界安排目标平台检查，浏览器替身不代替原生结果。

### M6 多视图与扩展贡献

**触发条件**：同一会话确实需要多个视图，或出现可复用的解析需求。

先用事件列表、字节预览或一个解析示例验证共享读取与状态重建，再决定是否增加工作区持久化或插件贡献点。验收视图重建不重连数据源、缺口与回放结果一致；涉及插件时再验证提供者失效与配置保留。只有实际复用需要才扩展公共注册或解析契约。

### M7 按需交付与作者工具链

**触发条件**：包体、编译成本或外部作者需求已经形成可测的问题。

先测量相关依赖和运行成本，再决定是否拆出原生包、SDK 或预编译 CLI。独立交付时明确所支持的平台和版本，验证签名、启动、停止及升级失败恢复；私有渠道、依赖求解等能力由实际分发需求决定。

## 并行开发与 Git

后续工作遵循 [Git 协作规范](../conventions/git-workflow.md)。需要并行时，先约定共享契约与文件分工即可；本次基础实现的临时分支、worktree 和提交顺序不作为长期流程。

## 验证与发布边界

按实际改动选择 [日常验证范围](../testing.md#日常验证范围)；虚拟会话、记录和 CLI 的命令集中在 [Rust 测试](../testing.md#rust-测试)。新增 IPC、数据来源或分发包时再补对应检查，不将虚拟数据吞吐或 CI 配置写成目标平台的实测保证。

## 复查与后续细化

若当前 crate 的链接成本阻碍无头开发，或新来源不能复用现有事件模型，先评估缩小接口或拆出领域 crate。其余扩展由已选场景推动，避免提前承担多层协议和分发机制的维护成本。
