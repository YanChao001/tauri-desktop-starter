# 设计提案模板

这是 [高影响设计](./engineering-at-scale.md#设计评审与-adr-门槛) 的写作提纲，可直接用于 issue / PR。只保留实际涉及的章节；普通局部改动使用 PR 模板即可。需要跨会话维护的方案再按 [文档层级](./engineering-at-scale.md#文档层级与维护职责) 保存为计划，长期取舍记录到 [ADR](./adr/README.md)。

```markdown
# 设计：要解决的问题

- 状态：讨论中 / 已采纳 / 已取消 / 已实施
- 受影响模块：
- 关联需求、PR、ADR：

## 问题与验收

触发场景、当前行为、期望结果与本次范围。
列出能判断完成的验收条件。

## 方案与取舍

当前结构及拟改变的依赖、数据和生命周期；公开入口和责任归属。
有实质取舍时比较可行方案，说明选择与代价；必要时用简图表达。

## 契约与失败路径

只说明变化的契约：调用方、数据归属、输入、错误或异步生命周期。
涉及不可信输入、权限、并发或副作用时，说明相应校验和失败结果。

## 兼容、发布与恢复

仅在影响存量数据或分发时填写：受影响格式、实际支持的升级起点、
迁移与失败恢复方式，以及需要协调的发布步骤。

## 验证与落地

按风险选取验证层和具体场景；性能改动注明同环境基线与比较口径。
列出实施步骤、需要更新的文档和仍待解决的问题。
```
