# 设计提案模板

达到 [设计评审门槛](./engineering-at-scale.md#设计评审与-adr-门槛) 时，将模板复制到 issue 或 PR，只保留相关项；不适用的兼容与恢复事项说明原因。需要随代码维护的跨里程碑方案可按 [文档层级](./engineering-at-scale.md#文档层级与维护职责) 放入 `docs/plans/`，PR 引用该计划，不重复维护。落地后同步当前文档，长期取舍记录到 [ADR](./adr/README.md)。普通局部改动直接在 PR 说明，无须另建提案。

```markdown
# 设计：要解决的问题

- 状态：讨论中 / 已采纳 / 已取消 / 已实施
- 负责人、受影响模块及评审人：
- 关联需求、PR、ADR：

## 问题与验收

触发场景、当前行为、期望结果；必须满足的约束和本次范围。
列出可验证的验收条件；性能项注明目标设备、测量口径和数字预算。

## 方案与取舍

当前结构及拟改变的依赖、数据和生命周期；公开入口和责任归属。
比较沿用现状和可行替代方案，说明选择与代价。
重要流程可画简图，不为普通函数绘制整套架构。

## 契约与失败路径

调用方和订阅方、输入范围、错误、超时 / 取消、并发及重试。
数据归属、权限和敏感信息；明确失败时用户看到什么、数据保留在哪里。

## 兼容、发布与恢复

受影响的设置 / 数据库 / IPC / 文件格式，支持升级的历史版本。
迁移步骤、失败后的状态和恢复方式，旧版本能否读取新数据。
发布顺序、验证平台、停止发布的条件和恢复负责人。

## 验证与落地

关键单元 / 契约 / 真实桌面场景，正式安装包与历史数据验收。
性能基线和前后对比、未验证范围及原因。
实现任务、需要同步的权威文档、尚未解决的问题及负责人。
```
