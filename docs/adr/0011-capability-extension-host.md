# 11. 通过能力宿主组合扩展贡献与受控效果

- 状态：已采纳
- 日期：2026-10-24
- 决策者：仓库维护者（授权开发阶段重构）、编码智能体（实现自审）
- 相关：[扩展指南](../extensions.md)、[0007](./0007-extism-extensions.md)、[0009](./0009-extension-surfaces.md)、[0010](./0010-curated-extension-market.md)

## 背景与验收

现有扩展已支持安装、签名市场、Wasm 与宿主绘制的页面，但网络只访问演示站点，权限全部必选，缺少持久化和独立输出。全局单次执行、不可中断的进程内编译及笼统错误也妨碍多窗口使用和第三方开发。

本轮按维护者要求全面重构，开发态不保留旧扩展协议兼容层。验收以可用工作流为准：离线功能无需授予网络；声明的真实 HTTPS 服务和显式本机服务可用；私有数据能跨进程保留；生成内容可由用户保存；多个窗口可排队、取消；编译与执行均可终止；错误和兼容问题在开发工具中可定位。既有文件、笔记、设置、恢复和关闭协商继续遵循各领域契约。

## 参考与取舍

借鉴 [VS Code 清单](https://code.visualstudio.com/api/references/extension-manifest) 的声明式贡献和宿主版本约束，以及 [Extension Host](https://code.visualstudio.com/api/advanced-topics/extension-host) 的执行分离；不引入 Node 运行时或 VS Code API 兼容层。

借鉴 [Chrome 可选权限](https://developer.chrome.com/docs/extensions/reference/api/permissions) 的按需授权，以及 [短生命周期服务的持久化原则](https://developer.chrome.com/docs/extensions/develop/concepts/service-workers/lifecycle)；不依靠常驻实例内变量保存业务数据。

借鉴 [DeepSeek Harness 架构](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/architecture.md) 的类型化服务、贡献登记与卸载清理。当前产品保留一个明确的能力宿主，用类型化效果组合实际服务；不增加通用依赖注入容器、任意服务替换语言或插件之间的隐式调用链。

| 方案                      | 收益                                           | 代价与结论                                   |
| ------------------------- | ---------------------------------------------- | -------------------------------------------- |
| 只放宽现有白名单          | 改动少                                         | 无法解决持久化、输出、调度、开发诊断，不采用 |
| 任意 Node / Web 页面插件  | 生态广、界面自由                               | 增加运行时、系统权限与分发边界，本轮不采用   |
| Wasm 能力宿主与类型化效果 | 复用现有技术，系统操作集中校验，可组合、可测试 | 维护有限公共协议与效果调度，采用             |

## 决策与契约

- 包格式 3、API 2、视图版本 2、注册表 schema 3。命令各自声明输入、结果、入口和所需能力；清单声明最低宿主版本、必需 / 可选能力与精确网络来源。内置和第三方扩展采用同一执行协议。
- 必需能力决定能否启用，可选能力可以拒绝或之后调整；没有获得某项能力时，不影响不依赖它的命令。原生每次执行仍校验已安装版本、授权和内容哈希。已验签的同市场来源或内置包在权限与网络范围不扩大的明确升级中可以保留原授权；本地包或扩大权限的升级重新确认，新增可选能力不自动授予。
- 插件通过受限 HTTP 与私有存储效果请求服务，宿主验证后将结果交回插件。效果有次数、字节、时间和取消预算；不接受任意 IPC、路径、Shell 或宿主对象。外部系统已经完成的请求不因取消而回滚。
- 网络来源是精确 origin 和方法集合。公开服务采用 HTTPS、地址校验和解析固定；本机 HTTP 只在单独声明并授权本机网络能力时可用。凭据由系统凭据服务按扩展、来源及别名隔离，插件仅持引用，不能读取原始密钥。
- 插件私有 JSON 存储有命名空间、revision CAS、配额与原子写入；损坏和未来版本拒写。卸载保留数据，清理是独立明确操作。结果产物经过格式和大小校验，只在用户选择保存位置后写出。
- 视图保留宿主绘制，增加受限图表、图片、进度、日期、字段校验与分页展示；所有输入、状态、结果和产物都有总预算。会话导入不得重新授予文件资源，也不能代替插件自己的状态校验。
- 调度采用最多两个执行位置和有界等待队列，同一窗口串行。关闭使该窗口旧请求失效，取消等待与停止执行语义分开。固定自身可执行程序的 worker 协议在 Tauri 初始化前处理，执行普通 Wasm，不执行任意原生程序；父进程对编译、初始化及执行统一计时，超限或取消时终止并回收本次 worker。
- worker 复用有界编译缓存，每次调用仍创建新实例。不继承宿主环境、目录与插件标准输出。进程分离用于资源和故障恢复，不声称构成额外操作系统权限沙箱。
- 市场记录来源和公钥指纹，目录有效期与跨重启最高 revision 防止接受过期或已知旧目录。目录签名证明市场维护者发布，不认证包内作者。显式回退保留前一包，撤回授权后由用户重新启用。
- 开发工具复用 Rust 清单和 Wasm 校验，不执行初始化完成预检；示例、打包、离线 smoke、内置资源重建使用同一协议。

## 兼容、失败与恢复

此次不迁移旧开发态扩展包、注册表或市场目录。遇到不支持版本时明确拒绝并保留原件，由开发者归档后重建；不删除设置、笔记或外部文件修复扩展错误。新市场目录需要独立市场仓库配套构建和发布，修改代码不代表线上已发布。

私有存储与凭据互不混存，卸载或升级失败不清除用户数据。worker 崩溃、取消或超时不会解除尚未完成的原生副作用；存储采用 CAS，产物保存仍需要系统对话框。安装回退和市场目录防回退是两个不同操作：前者由用户显式选择，后者防止分发端静默返回旧信任状态。

## 验证与复查

验证清单 / 权限 / 来源边界、可选授权、CAS 与损坏拒写、网络地址分类和取消、效果轮次、真实 Wasm 存储和产物、worker 整体超时与崩溃恢复、有界队列与窗口关闭、市场重启防回退和签名过期。前端覆盖键盘、焦点、输入保留、会话导入、权限变更及浏览器边界；无头浏览器检查布局和自动无障碍。

不为此次重构启动用户桌面上的真实 WebView 或安装器。正式安装、多窗口系统行为、签名及其他平台仍在独立环境验收。出现必须运行长驻任务、实时流、自绘界面或插件间依赖的真实需求后，再评估增加相应协议，不预建空扩展点。
