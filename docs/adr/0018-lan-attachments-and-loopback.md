# 18. 通过受控附件与真实回环扩展内网通信

- 状态：已采纳
- 局部取代：[0013](./0013-extension-desktop-services.md) 的 LAN 仅文本范围；受控固定服务、授权、窗口归属及明文信任边界继续生效。
- 日期：2026-10-27
- 决策者：维护者要求实施聊天界面、附件与本机回环；编码智能体按数据、权限、失败和发布边界自审与分层验证，不虚构第二位审批人
- 相关：[扩展指南](../extensions.md#局域网通信)、[安全规范](../security.md#能力最小化)、[市场插件说明](../../marketplace/plugins/lan-chat/README.md)、[0012](./0012-extension-ui-surfaces.md)

## 背景

内网聊天需要发送图片、文件和表情，并在没有第二台设备时验证真实通信。原有文本服务的手动监听、IP 与端口常驻主界面，打断会话阅读；浏览器内模拟回声虽方便演示，无法验证原生 TCP、附件保存和送达回执。

扩展此功能会扩大已存在的 `messaging:lan` 授权范围，并引入附件持久缓存与新的消息协议。若直接向隔离网页开放路径、文件系统或任意 IPC，原有按插件、安装代次与窗口核验的固定服务边界将失去作用。当前需求也没有账户、远程身份认证、云中继或加密协议基础，不能用聊天软件外观暗示具备这些能力。

## 备选方案

| 方案                                                                | 收益                                                         | 成本与限制                                                     |
| ------------------------------------------------------------------- | ------------------------------------------------------------ | -------------------------------------------------------------- |
| 保留纯文本，界面模拟附件与回声                                      | 改动和资源成本低                                             | 无法完成实际图片 / 文件通信，不能验证原生链路，不采用          |
| 向网页开放文件路径、网络与任意 IPC                                  | 便于添加常见聊天功能                                         | 绕过受控能力、路径与窗口生命周期边界，权限过大，不采用         |
| 增加通用文件平台及独立账户 / 加密服务                               | 可支撑更大通信产品                                           | 引入当前没有需求与运维基础的协议、身份、密钥和后台职责，不采用 |
| 扩展固定 LAN 动作、私有缓存与原生选择 / 另存，提供真实 TCP 回环助手 | 满足当前消息、附件和本机验证需求，复用已有授权与资源生命周期 | 需维护有界帧、图像校验、缓存完整性及协议演进，采用             |

## 决策

插件更名“内网通信”，保留 `market.lan-chat` 身份与已有本机历史归属。隔离 HTML 负责会话列表、消息气泡、输入区、表情选择、图片 / 文件卡片与受控预览；连接、昵称、监听与本机回环收在默认关闭的设置面板。Wasm 继续验证并生成纯文本导出，附件以名称与大小标签保留，不将文件字节嵌入文本导出或草稿检查点。

所有通信仍通过 `starter.services.request("lan", request)`。附件发送只能由原生文件对话框选择实际文件，另存通过系统对话框决定目标；服务不接受网页或远端指定的系统路径，不自动打开或执行文件。图片通过真实格式解码与像素预算验证，界面取得有界缩略预览；普通文件只返回元数据卡片。附件按插件保存在服务私有缓存，执行单文件、总量、普通文件 / 链接检查与内容 SHA-256 校验，不依赖文件后缀证明图片类型，也不将散列当作远端身份认证。

沿用 `messaging:lan`，授权文案明确说明收发文字、图片和文件、保存本机历史及受控选择 / 另存的范围。此次不增加 Tauri capability、CSP、通用文件 API、Shell、任意 IPC、系统剪贴板或远程页面入口；不新增直接依赖，图片、散列、对话框和原子写入复用宿主已有能力。任何新增更广的文件动作仍须重新评审授权与边界。

本机回环在 `127.0.0.1` 随机端口启动原生节点和独立助手，执行与局域网相同的 TCP 握手、收发及 ACK，并回送收到的文字、表情和附件。它使用相同的额度、存档和窗口生命周期，界面显示明确的回环模式与助手会话。模式切换停止当前连接，导航保留已开启服务；明确停止、最后一个使用窗口关闭、撤权、替换、卸载与退出回收本次服务创建的连接和工作线程。

## 协议、数据与失败

消息协议升级到版本 2，明确拒绝版本 1，不维护未承诺的开发快照协商层。历史 schema 2 对原有 schema 1 文本数据执行受校验迁移；未知、未来、损坏、超限或链接存档拒写并保留原件，不能通过清空用户数据修复协议变化。精确请求、额度与缓存规则由 [扩展指南](../extensions.md#局域网通信) 和实现集中维护，不在 ADR 复制易变值。

发送成功写入连接与对端持久保存 ACK 分开表示；缺回执或前端停止等待都不等于未发送，不自动重放。取消文件对话框不产生成功消息；附件存档、读取或另存失败须保留原有记录与用户草稿，不把预览缺失冒充聊天记录丢失。撤权与安装维护继续等待已开始的受控服务调用结束，最终提交复核窗口与安装身份。

当前宿主使用 `0.1.7` 开发基线，插件提升到 `1.1.0`，双方需从配套源码重新构建；旧同版本快照不具有新服务实现。此决策不表示宿主安装包或线上市场已发布。正式分发按现有跨仓库流程选择已审核的宿主提交、提升发布版本和准确最低宿主，再验证插件，不以清单字符串或 CI 配置代替真实运行证据。

## 后果与验证

用户可在熟悉的聊天布局中进行真实消息与附件交流，并用一台设备验证原生链路；网页保持有限固定动作，不获得任意文件权限。代价是原生服务需要额外处理有界附件、预览、缓存与协议 / 存档升级。聊天、附件与本机历史仍为明文，昵称和节点身份可由远端声明，只适用于用户信任的网络。

验证按边界分开：原生测试覆盖真实双端 TCP 和回环助手、握手与 ACK、附件格式 / 大小 / 内容完整性 / 路径 / 缓存额度、旧文本迁移及未来版拒写、停止与窗口 / 撤权回收；Wasm 验证双语入口、真实文本与附件标签导出；无头界面验证默认收起设置、键盘焦点、模式切换、表情 / 附件入口、晚到响应与草稿保留。两台设备、系统选择 / 另存对话框、真实 WebView 图片预览、目标平台和正式安装包仍需单独验收，不以浏览器替身或本机回环代替。

## 复查条件

当需要跨网段或云中继、远端身份认证、加密、可靠断点续传、更大附件、自动接收目录、后台常驻或跨设备同步时，重新评估协议、授权、密钥、缓存与任务归属；不能通过放开任意路径、隐藏无限缓存或自动执行附件延伸本决策。
