# 16. 有界保留最近使用的插件界面

- 状态：已采纳
- 局部取代：[0012](./0012-extension-ui-surfaces.md) 中“离页使旧端口失效”的默认策略；sandbox、CSP、能力 broker、安装身份与原生租约复核保持。
- 日期：2026-10-27
- 决策者：维护者要求重构插件体验；按方案、失败路径和兼容边界自审，不虚构第二位审批人
- 相关：[架构说明](../architecture.md#页面与演示边界)、[扩展指南](../extensions.md#自定义界面)、[界面 SDK](../../sdk/README.md#活动状态与页面保留)、[测试规范](../testing.md#自定义扩展界面)

## 背景

本地工作台首次打开比宿主页面慢，打开过后再次切换仍有重建和闪烁。宿主静态入口已有代码预载，动态插件入口未复用同一路径；自定义 HTML 首屏还承担通用结果渲染器的无关解析依赖。离页立即销毁 iframe，返回时需要重新申请界面租约、解析文档、连接端口、同步主题并完成首屏握手。会话恢复能保留已登记草稿，不能消除这些重复呈现成本。

工作台的高频场景切换、画布编辑、数据筛选和流程模拟属于本地界面交互。将这些操作交给 Wasm 或用整块 DOM 替换呈现，会扩大延迟和布局变化；界面应保留自己的模型，通过检查点恢复，需要导出或宿主能力时才调用既有边界。主进程生命周期、原生任务与用户数据恢复不随这次体验改动改变。

## 备选方案

| 方案                               | 收益                               | 成本与限制                                                                   |
| ---------------------------------- | ---------------------------------- | ---------------------------------------------------------------------------- |
| 每次离页立即销毁，返回时从会话重建 | 释放文档与监听最及时，生命周期简单 | 每次重走文档解析与握手，未登记局部状态丢失；增加预载只能减少模块等待         |
| 保留所有访问过的插件页面           | 回访可直接显示，局部模型自然保留   | 文档、监听、Canvas 与第三方循环持续累积，没有可解释的资源上限                |
| 保留最近使用的最多 3 个插件页面    | 常用页面可直接回访，文档数量有界   | 增加活动状态、隐藏请求拒绝与 LRU 清理；3 是初始文档预算，不是内存或 CPU 配额 |

选择有界保留，并同时补齐动态入口的纯代码预载及不活动页面的行为边界。预载只加载前端模块，不挂载插件、申请租约、读取私有数据或执行 IPC / Wasm。

## 决策

每个主 / 次窗口的 AppShell 保留最近使用的最多 3 个插件 outlet，包含当前页面。LRU 只更新使用顺序，不重排已挂载节点的 DOM 顺序，避免移动 iframe 重建其浏览上下文。非当前页面使用 `hidden` / `inert`，退出布局、焦点顺序与辅助技术交互；普通宿主路由仍按原来的按需加载与错误边界呈现。

宿主向界面快照增加可选 `active` 布尔值；新宿主总发送，旧宿主缺省视为 `true`。隐藏页面保留 MessagePort，但 SDK 和宿主桥均拒绝新的界面请求。此限制涵盖绕过 SDK 的手写消息，不能将隐藏状态当成后台执行资格。已经提交的请求继续接收真实回执，不因切页自动取消，也不宣称副作用回滚。

不活动时暂停执行阶段轮询、Wasm 语言刷新、主题与尺寸观察以及握手 / 首屏 watchdog；恢复时读取最新设置并重新给予可见等待预算。SDK 同步 `data-active` 并暂停默认 CSS 动画、收起增强 select、停止主题过渡；`data-motion` 保留用户动效偏好。作者仍须根据活动状态、文档可见性、离屏和减少动效停止自己的动画、定时器与轮询，SDK 不接管任意脚本或第三方循环。

超出上限移除最久未使用的界面，释放文档、端口和界面租约；既有会话缓存、未保存工作回调、state、字段和检查点独立保留，继续保护脏工作和在途操作。返回时可以重建文档并恢复登记过的模型，不能保证恢复仅存在于 iframe 局部变量中的状态。

安装 generation / 包哈希 / 版本变化、禁用、卸载或必需命令授权不再满足时，立即移除相应旧页面；可选授权变化只同步最新快照。每次实际原生能力调用继续复核当前窗口、安装身份和授权，保留原有租约撤销、关闭与晚到结果隔离语义。此决策不增加 IPC、权限或依赖，不调整 CSP 或 sandbox，不扩大后台原生服务范围。

## 兼容与失败路径

活动字段是 SDK 快照的可选增量，不升级包格式、API、视图协议或已有注册表 schema。旧插件注入新 SDK 后可获得 CSS 动画暂停与请求拒绝；自行创建的循环仍需作者适配。只依赖旧字段的作者在旧宿主上仍按活动处理，不通过伪造减少动效补偿缺失的活动协议。

本地工作台 2.3.0 的场景模型保存在 SDK 检查点，Wasm 会话仍为 schema 3，已有文本、数据和待办草稿可读。工作成果导出在既有字段与动作协议内进行有界校验，不把界面 payload 塞进 Wasm state，不删除用户数据修复界面问题。

隐藏前未及时登记的局部状态可能在 LRU 移出后丢失，因此编辑发生时就应同步字段 / 检查点，不能等隐藏后再发送请求。请求失败保留输入；原生回执尚未到达时不自动重试有副作用的动作。损坏资源、首屏失败和过期身份沿用现有错误及重试入口，不以常驻隐藏文档掩盖失败。

## 后果与验证

回访常用插件可复用文档、连接和局部模型，高频工作台交互不等待 Wasm。代价是最多额外保留少量隐藏文档及其内存，需要维护活动协议与双层请求拒绝；文档数量有界不等于 UI 脚本执行可抢占，也不提供逐 iframe CPU / 内存配额或跨平台独立 renderer 保证。

验证覆盖纯预载、稳定 DOM / iframe、隐藏布局与焦点、后台请求拒绝、在途回执、轮询与计时暂停、LRU 草稿恢复、身份与必需授权失效，以及 SDK 缺省活动兼容。工作台另验证场景切换、检查点、动效清理和真实 Wasm 导出的边界；具体命令与 fixture 分层由 [测试规范](../testing.md#自定义扩展界面) 维护。

本记录表示方案已采纳，不表示全部检查或 Windows / macOS / Linux WebView 已通过验收。无头 HTML fixture、生产 React 外壳加离线 Wasm、原生 IPC 与正式安装版分别提供证据；实际执行结果与未测范围随交付说明，不将 CI 配置或浏览器表现写成平台实测。冷 / 热启动改善需在相同目标环境按 [性能采样](../testing.md#安装版与启动验收) 比较。

## 复查条件

若隐藏文档导致可测的内存增长、第三方循环持续占用 CPU、焦点 / 输入法 / 无障碍回归，或 3 项预算对常用工作流频繁淘汰，应重新评估预算、暂停适配与保留范围。若产品需要可靠终止失控 UI 或承载真实后台工作，应单独选择可终止执行边界或原生服务协议；不通过无限保留 iframe 扩展本决策。
