# 20. 将应用更新验签公钥固定在安装包内

- 状态：已采纳
- 日期：2026-10-28
- 相关：[更新通道](../security.md#更新通道)、[自动更新](../build-release.md#自动更新)

运行期部署文件与更新签名承担不同职责：部署文件选择镜像和开关，安装包内置公钥决定哪些更新可信。允许用户目录中的同一份 JSON 同时更换地址与公钥，会让普通配置污染转变为对另一套签名的信任，因此公钥只来自编译期品牌配置；部署文件中的同名字段仅允许复述相同值，不匹配时拒绝更新。

保留可写公钥便于受控部署换钥，但依赖每个平台额外保证配置完整性；将配置移到提权目录也无法统一覆盖当前用户安装和便携分发。选择内置公钥后，镜像切换和禁用更新仍可独立完成，换钥及首次启用更新则需要可信安装包。正常换钥使用旧钥签发包含新公钥的过渡版本，离线客户端通过手动可信安装迁移。

此决定不提供操作系统级沙箱，也不承诺抵御已经替换宿主二进制的同账户攻击。若以后需要独立于应用版本的密钥轮换，须先设计可验证的密钥过渡协议，再复查本决定；不能重新以普通部署文件作为信任根。
