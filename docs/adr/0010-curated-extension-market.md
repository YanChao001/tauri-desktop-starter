# 10. 通过独立仓库发布受控扩展市场

- 状态：已采纳
- 日期：2026-10-24
- 决策者：仓库维护者（确认方案）、编码智能体（实现自审）
- 相关：[扩展指南](../extensions.md)、[0009](./0009-extension-surfaces.md)

## 问题与影响

维护者需要控制插件上架、版本和下架，在应用内发现、下载和更新插件，同时保留内置离线扩展与本地包导入。影响扩展中心、原生下载边界、IPC、发布流程与仓库协作；不改变 Wasm 运行权限或执行模型。

## 方案与取舍

沿用本地导入不能提供发现和版本提示；任意 GitHub 搜索不能保证收录权；独立账户后台引入当前无需的服务运维。采用维护者拥有的公开市场仓库，以 GitHub PR 和发布权限管理收录，GitHub Releases 分发包与签名目录。

主项目在 `marketplace/` 以 Git submodule 引用市场仓库。内置实验室源码与模块保留在主仓库，正常应用构建不依赖市场子模块或在线服务。用户安装数据继续保存在应用数据目录。

## 契约与失败路径

- 应用配置固定市场仓库与目录验证公钥。签名目录包含完整扩展清单、模块哈希、完整包哈希、大小、分类及发布附件位置；客户端不接受用户提供的下载 URL。
- Rust 负责有界 HTTPS 下载、重定向目标校验、签名、目录结构与包一致性校验。复用现有依赖，不开放 WebView 通用 HTTP 或文件权限。
- 浏览器保持原生能力限制。桌面刷新失败保留当前会话中已验证的目录并标明过期；安装只接受重新确认仍在市场的版本。失败不改安装记录，不执行插件。
- 市场与本地包共用审阅、安装、授权和升级撤权流程。下载安装后默认禁用；更新由用户明确确认。同 ID 的包仍需审阅内容，目录签名表示市场维护者发布，不证明作者身份。
- 下架停止新的市场下载，不远程删除用户已安装的数据。第一版不提供账户、支付、多市场源或远程强制卸载。

## 发布与恢复

当前处于开发阶段，直接定义新的市场契约，不为旧市场格式建立兼容分支。既有本地扩展存档与安装接口保持职责不变。签名私钥只进入本机临时密钥文件与市场仓库 Actions Secret，不进入任何 Git 仓库或客户端。

先验证市场源码、打包和签名，再创建市场仓库、配置发布密钥、上传首个可验证版本，最后关联子模块。后续更新先发布附件，再发布引用附件的签名目录；回退推荐版本仍需发布更高目录 revision。

## 验证与代价

验收签名与包篡改、清单不符、重复 ID、目录回退、超限与重定向边界、下架后拒绝下载、失败保留安装数据、发现与更新提示、审阅后安装及授权。执行前端、脚本、Rust、绑定和无头界面检查；真实桌面与其他操作系统验收另行记录。

代价是维护一套签名发布流程和子模块提交引用。扩展市场达到需要商业交易、私有分发或大量资源的规模时，复查专用服务与存储方案。
