# 19. 按命令声明有界计算预算

- 状态：已采纳
- 日期：2026-10-27
- 决策者：维护者授权移植 Slither 并优化必要宿主能力；实现按信任、资源、取消和兼容边界自审
- 相关：[扩展指南](../extensions.md#执行存储与生命周期)、[0011](./0011-capability-extension-host.md)、[0017](./0017-precompile-enabled-extensions.md)、[测试规范](../testing.md#rust-测试)

## 背景与影响

移植后的 Slither 在界面本地逐帧运行，保存纪录时由 Wasm 从种子和输入重放核验。实际 fixture 中短局可以通过原计算额度，较长的有界重放会耗尽 fuel；提高所有插件的默认额度会无关地增加失控模块的可执行工作量。需要在不扩大文件、网络或原生执行能力的前提下支持这一实际计算负载。

范围覆盖命令清单 DTO、版本校验、真实运行和离线 CLI、worker 固定协议、启用预编译、生成绑定与市场字段校验。插件业务仍负责限制重放长度、动作数量和状态大小；宿主的预算不能替代业务边界校验。

## 备选方案

| 方案                                | 收益                     | 代价与结论                                                                   |
| ----------------------------------- | ------------------------ | ---------------------------------------------------------------------------- |
| 全局提高默认 fuel                   | 修改最少                 | 所有插件均获得更多可执行工作量，不采用                                       |
| 按插件 ID 放宽或由前端指定任意 fuel | 容易满足当前游戏         | 宿主混入插件业务，或允许调用方绕过清单，不采用                               |
| 将重放分片并跨调用保存验证状态      | 单次计算较少             | 引入中间状态信任、额外往返和恢复协议，当前没有需要承担这些成本的证据，不采用 |
| 清单命令选择固定预算档              | 范围明确、可复用、可测试 | 增加一个字段及版本门槛；混合档位占用多条编译缓存，采用                       |

## 决策

命令新增可选 `executionBudget`，仅接受 `standard` 和 `compute`。省略保持原标准额度，计算档用于明确有界的计算并要求配套宿主版本。精确额度及当前兼容门槛只在[扩展指南](../extensions.md#执行存储与生命周期)维护。

运行预算只来自原生已校验的安装清单；原生前端请求、SDK 和效果不新增覆盖预算的入口。真实应用调用、每一轮效果和 CLI fixture 使用同一命令档位，经固定 worker 协议传入运行时。未知档位在清单或 worker 解码边界拒绝，不提供任意 fuel 数字或无限档。

计算档只增加初始化和导出执行可用的 fuel，保留原墙钟、内存、IO、排队、效果、合作取消和 worker 回收规则，不新增权限或系统能力。缓存按 fuel 区分；启用预编译和启动预热准备清单实际使用的档位，不创建实例，两档共享原单项总时限并各自占用既有缓存预算。[0017](./0017-precompile-enabled-extensions.md) 的实例隔离和缓存失效结论继续有效。

## 兼容、失败与验证

新增字段不能由旧二进制支持；使用计算档的包声明新最低宿主版本，开发快照和本地构建不表示正式宿主或市场已发布。未声明的既有命令保持标准预算和原序列化形态；不为早期开发快照增加多版本解释器或迁移。未知或未来存档继续保留原件并拒写。

计算档仍可能耗尽 fuel、到达墙钟或被取消；这些情况沿用稳定错误码，保存纪录失败不得伪造成核验通过。扩大预算不会回滚已提交的原生效果，也不能延长会话完整动作的总期限。

回归须分别验证清单默认值、非法值和版本门槛；同一真实模块以标准档耗尽、计算档完成、再以标准档耗尽，防止缓存泄漏预算。真实 worker 和 CLI 另行覆盖固定协议、取消后回收及后续正常调用；实际长局 fixture 用真实 Wasm 证明新额度能承载需求。测试结果随交付记录，不将进程内或浏览器测试当作原生安装版验收。

## 后果与复查

计算插件可完成更长的有界工作，代价是单个执行位在原墙钟范围内可能消耗更多 CPU；混合预算也可能更早淘汰编译缓存。若实际重放继续触顶、交互被长计算占用、启用编译等待过长，或需要跨调用可信断点，应重新评估业务算法、分片验证及队列公平性；不能继续抬高全局默认额度、扩大系统权限或复用有状态实例。
