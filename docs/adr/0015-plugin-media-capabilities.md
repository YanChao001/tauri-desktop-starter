# 15. 由插件实现图片供应商并复用受控媒体能力

- 状态：已采纳
- 日期：2026-10-26
- 决策者：维护者授权补齐实际插件所需能力，编码智能体实施自审与分层验证
- 相关：[扩展指南](../extensions.md)、[架构说明](../architecture.md)、[安全规范](../security.md)、[测试规范](../testing.md)
- 局部取代：[0013](./0013-extension-desktop-services.md) 中壁纸服务承担远程供应商业务的边界，以及 [0014](./0014-bing-image-search.md) 中由原生宿主解析 Bing、签发供应商结果标识和兼容 Commons 的实现决策；LAN、图库与设置的数据归属、授权和生命周期约束继续生效。

## 问题与验收

原壁纸市场包负责界面，Bing URL、请求参数、网页解析、结果缓存和 Commons 兼容均在原生宿主。搜索网页结构变化或更换供应商必须重发桌面程序；只拆分原生文件仍不能让插件独立修复业务。系统对话框、图片解码、宿主图库和设置则确实需要受控原生能力，不能随供应商代码一起交给插件。

本次将搜索请求构造、供应商解析和来源文案完全交还插件，宿主提供已有 HTTP 效果的代理选项、有界图片资源、图库与安全外链能力。插件可在不授予新网络能力时继续使用本机图库。供应商变更只要满足这些稳定能力的契约，即可通过市场包更新；新增宿主能力仍需提高最低宿主版本。

影响范围为 Rust 权限 / 网络 / 服务 / 生命周期、生成绑定、隔离 UI SDK、壁纸插件与市场元数据、相关测试和文档。复用已有网络、图像、哈希、随机标识和存储依赖，不以本次需求增加通用插件服务注册器、任意 IPC 或原生代码加载。系统剪贴板、操作系统通知和通用后台任务没有本轮真实调用者，不预建入口；宿主 toast 和固定 LAN 服务不被称为这些通用能力。

## 方案与取舍

| 方案                                          | 收益                                                 | 代价与结论                                     |
| --------------------------------------------- | ---------------------------------------------------- | ---------------------------------------------- |
| 保留宿主 Bing / Commons 服务                  | 来源证明继续集中在宿主，改动最少                     | 网页解析和供应商更新仍绑定桌面发布，不满足目标 |
| 仅把原生代码拆成 provider 模块                | 减少单文件职责混杂                                   | 发布边界不变，不作为独立更新方案               |
| 插件实现供应商，宿主提供受控网络和图片资源    | 搜索业务随签名市场包更新，图库和系统边界保持原生校验 | 必须明确改变来源信任和网络权限，采用           |
| 放开隔离网页网络、任意 URL 下载或任意原生服务 | 接入灵活                                             | 绕过来源授权、内容额度或生命周期，不采用       |

数据流为：插件 Wasm 通过已授权 HTTP 效果取得搜索文本并解析候选图片；隔离界面请求宿主下载候选图片，取得不透明 `resourceId`，再用同一资源进行预览、另存或图库导入。宿主没有 Bing / Commons 解析器，也不接收插件提供的路径或可执行命令。

**来源信任发生明确变化。** 搜索关键词、供应商响应、图片归属和许可解释由经过审核的插件负责；宿主不再证明某 URL 来自 Bing 搜索。`network:images` 允许取得任意公网 HTTPS 的 GET 图片资源，URL 查询本身也可能向原站发送数据，不能把它描述成只访问受信供应商。宿主独立核验当前授权、URL / DNS / TLS、响应和图片内容；目录签名不能代替用户对这些权限的审阅。

## 契约与失败路径

### 网络与代理

既有 HTTP 效果新增 `networkMode`：省略时仍为 `direct`，不改变旧请求的禁代理行为；`system` 额外要求独立的 `network:system-proxy` 授权。精确 origin、方法集合、正文 / 响应 / 时间额度及凭据来源规则继续生效。环回 HTTP 不允许 `system`。

`system` 使用用户系统 / 环境代理和 `NO_PROXY`。未选中代理或命中排除规则时，目标 DNS 仍必须通过公网校验并固定本次地址；代理传输主机可以位于本机或内网，插件不能自行指定代理地址或关闭 TLS。代理在远端解析目标时，宿主无法证明最终目标 IP 为公网；HTTPS、正常证书、禁止重定向和内容额度继续生效。新增权限确认必须解释这一边界，不承诺执行任意 PAC。

### 图片资源、图库与外链

- `resources` 服务要求 `network:images`，`fetch-image` 仅以 GET 下载公网 HTTPS 图片；`system` 同时要求代理授权。返回不透明资源 ID、实际 MIME、原图字节数、尺寸和 SHA-256。预览、用户另存、显式释放及图库导入均使用该资源 ID，不再次接受下载 URL。
- 接收的原图最多 16 MiB，只允许真实 JPEG / PNG / WebP；单边最多 8192 像素、总计 1600 万像素、解码分配预算 128 MiB。预览和加入图库执行受限重绘；另存保留经过检查的原图字节，并由系统对话框决定路径。
- 原生资源按 `Arc` 持有，缓存 TTL 为 10 分钟；每个窗口所有者最多 8 个资源 / 32 MiB，全局最多 32 个 / 64 MiB，下载和图库 / 资源图像处理共用 2 个名额。资源绑定插件 ID、安装代次、模块哈希和原生窗口 epoch，重启或释放后不可重新查找；`release` 不取消已取得资源的在途操作。关闭、撤权和替换清理对应缓存，最终提交仍复核生命周期；缓存限制不等于进程全部内存上限。
- `wallpaper` 只负责图库列表、本机导入、`import-resource`、应用背景、重命名、移除和打开背景设置，复用现有图库及设置 revision CAS；资源导入同时核验 `wallpapers:manage` 与 `network:images`。它不搜索供应商、不下载裸 URL，也不设置操作系统桌面壁纸。
- `links` 服务要求 `links:open`，按安全外链规则打开 HTTPS 来源页；不提供任意 IPC、Shell、文件路径或其他协议。

服务沿用当前安装身份复核、读写门闩和 `ServicePermit`。系统保存对话框可能等待用户操作；原图写入、图库与设置变更在最终提交前重新检查生命周期。图库缩略图的 CPU 工作移出提交窗口锁，预览忙或损坏时返回 `dataUrl: null`，不将已经成功的写入冒充失败。失败、超时、取消、资源过期和额度不足明确返回错误，保留已有图库、设置和用户草稿；网络或已完成写入不冒充自动回滚。前端不因停止等待而报告原生操作已取消。

## 兼容、发布与恢复

配套宿主提高到 **0.1.6**，壁纸包为 **1.0.3** 且声明 `minHostVersion: "0.1.6"`；包格式 3、API 2、视图版本 2、注册表 schema 3 保持不变。Rust 对声明 `network:images`、`network:system-proxy` 或 `links:open` 的清单强制最低宿主版本至少 0.1.6，不能由作者仅依赖同版本开发快照。新网络、图片和外链权限由插件按功能声明为可选，旧安装不自动获得新授权。新权限是闭集枚举增量，旧宿主可能在解析新目录时拒绝；不能靠刷新前端或只固定 CI 的 `host_ref` 补齐旧客户端。

新增能力也暴露出目录整体反序列化的演进问题。本次对已验签 schema 2 增加私有 wire 层：完整验证公共目录、包元数据与兼容头后，仅将明确要求更高宿主的未知清单正文隔离为只读摘要，不赋予下载或安装资格。当前可理解条目继续严格校验；完整原始 payload 摘要仍用于防回退，隔离不隐藏坏签名、重复键、坏附件或同修订替换。界面使用原生返回的宿主版本禁用已知不兼容下载和升级，具体规则由[官方市场契约](../extensions.md#官方插件市场)维护。

当前是尚未正式发行的开发阶段，不保留宿主旧 `search` / `resultId` / Commons `pageId` 供应商入口。旧壁纸 1.0.2 的搜索须升级到配套包；旧会话中的远程结果不作为新资源下载资格。已有图库、背景设置、注册表和私有数据 schema 不变，不删除用户数据，不通过归档图库解决兼容问题。

先使兼容宿主完整提交可被独立市场 CI 获取，再用确定 SHA 验证和发布插件；正式宿主与市场发布分别记录验证结果。若新网络边界、权限拒绝、资源身份 / 配额、最终提交或数据保留检查失败，停止发布；维护者修复后发布更高插件版本和目录修订，不降低市场信任水位。若显式回退旧包，其旧搜索仍不受新宿主支持，不能承诺恢复旧供应商服务。

## 验证与落地

实施须同步 [当前扩展契约](../extensions.md)、[运行结构](../architecture.md)、[权限边界](../security.md)、[验证范围](../testing.md) 和 [SDK](../../sdk/README.md)，并生成 IPC 绑定。市场独立维护供应商解析、清单、业务 fixture 和发布元数据；宿主不复制供应商规则。

验收要求包括 HTTP 的 direct / system 授权、精确来源 / 方法、`NO_PROXY` 与 DNS 边界；图片 URL / MIME / 实际解码及字节 / 像素 / 内存额度；TTL、配额、并发、跨窗口 / 安装身份拒绝、关闭 / 撤权清理和持有资源期间的保存；图库 CAS、真实保存取消与最终提交；安全外链；插件无网络授权的本机图库、供应商解析失败、真实 Wasm 效果往返和原始数据保留。浏览器替身、离线验签及源码检查不等于真实网络、系统对话框、WebView 或正式安装版验收；本记录不宣称这些检查已经执行或通过，实际命令、平台与结果写入 PR / 交付记录。

## 后果与复查条件

供应商网页变化可由插件发布修复；宿主仍需维护可复用媒体能力、动态图片来源的明确授权和资源生命周期。新增能力改变了原先“只访问原生认定的 Bing 结果”的信任范围，必须以真实权限文案和拒绝路径承担该代价。

出现第二种真实媒体类型、受信供应商来源证明、通用长驻任务、批量下载或必须跟随重定向的产品需求时，重新评估对应契约与预算；不以放开任意代理、系统路径或取消最终提交检查作为兼容办法。
