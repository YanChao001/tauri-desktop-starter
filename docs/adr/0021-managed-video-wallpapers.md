# 21. 用独立媒体副本保存视频壁纸

- 状态：已采纳
- 日期：2026-10-28
- 局部取代：[ADR 0004](./0004-wallpaper-library.md) 中“不保存动画”和当前壁纸完全自包含的限制；图片快照、独立图库、原子写入与恢复边界继续有效。
- 相关：[数据存储](../architecture.md#数据存储)、[媒体安全边界](../security.md#入参校验)

## 问题与方案

壁纸需要支持本机视频，并在重启后继续使用。将视频转换为 data URL 放进设置会突破有界设置快照并放大每次跨窗口同步；直接保存用户文件路径则依赖原文件长期存在，并把路径授权带入后续播放。因此视频保存为应用管理的独立副本，设置和图库只保存有界封面及内容引用，不引入转码依赖或放宽设置体积。

本机 MP4 / WebM 由系统对话框选择，Rust 校验头部、普通文件和大小后复制到受控媒体目录，以 SHA-256 和固定 MIME 定位；前端使用实际媒体解码结果生成封面，再加入图库。播放经仅供主 / 次窗口使用的专用协议，响应有界字节范围，不开放任意路径。浏览器演示将 Blob 放入独立 IndexedDB，播放时生成并释放 object URL，不冒充原生文件服务。当前额度和实现入口归[架构说明](../architecture.md#数据存储)维护。

## 契约、失败与恢复

设置 schema 升至 5，图库格式升至 2，支持读取已有纯图片图库后在后续写入时迁移；未来版本和损坏存档继续拒写。图片或视频导入失败时保留当前背景，部分导入成功项继续保留；已复制但未入库的媒体属于待回收副本，不能宣称已加入图库。媒体 URL 不持久化，视频缺失、解码或播放失败时使用已保存封面。播放静音循环，并遵循零透明度、减少动效、离屏、文档隐藏和卸载的暂停 / 释放策略。

删除图库条目不立即删除媒体文件，避免影响当前设置副本、其他窗口或正在提取封面的导入。导入前的回收保留图库与当前设置引用及近期导入副本；未知 / 损坏存档不能作为清理依据，额度不足则拒绝新导入，不能删除用户原始文件腾出空间。隔离恢复使用临时媒体目录，不触碰正式图库；现有笔记备份和启动恢复归档仍不包含图库与媒体，不能据设置中的引用推断视频已经备份。

## 影响与验收

本决定涉及图库 DTO、设置与图库格式、原生协议及 CSP `media-src`，没有新增通用文件权限或远程视频能力。方案自审关注有界存储与读取、跨窗口引用、未来格式拒写及恢复隔离；没有把自审记为第二位维护者审批。

回归须覆盖纯图片迁移、相同封面的视频身份、重启保留、部分失败和晚到结果；原生层验证文件与 ID / MIME 边界、Range、容量和清理保护，浏览器验证 Blob 持久化、URL 释放、封面降级与动效暂停。正式安装版的目标平台解码、实际耗电和长时间播放仍须按[桌面验证边界](../testing.md#避免干扰本机桌面)分别验收，单元测试和浏览器 fixture 不能代替。

需要跨设备同步、视频转码、媒体随备份迁移或更大图库时，应重新评估媒体归属和归档格式，不能继续增加设置 JSON 或无界播放缓存。
