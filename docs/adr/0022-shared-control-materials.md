# 22. 让宿主与插件共用完整控件样式和材质规则

- 状态：已采纳
- 日期：2026-10-29
- 相关：[界面规范](../conventions/ui-guidelines.md#颜色只用语义-token)、[界面 SDK](../../sdk/README.md#默认外观与动效)

## 问题与选择

宿主在 React 组件和业务 CSS 中绘制控件，隔离插件又在 SDK 中维护另一份默认 CSS。仅传语义颜色不能保证背景、边框、尺寸和选中状态一致，手写 token 名单还会漏掉后来增加的控件。原有 100% 背景透明度同时清空正文与导航的阅读遮罩，使固定主题字色无法在任意壁纸上保持清晰。

采用浏览器原生 CSS 作为共同来源：[surface-tokens.css](../../src/styles/surface-tokens.css) 定义材质配置与计算，[control-styles.css](../../src/styles/control-styles.css) 定义标准元素、语义角色及控件状态。宿主直接导入，现有主题快照将相同完整文本交给插件。SDK 不再另存一份控件 CSS，也不按当前文档已经出现的控件裁剪规则，因此之后插入的少见控件同样能匹配。已注册 ShadowRoot 沿用同一来源和更新路径。

继续复制两套样式的初始成本较低，但无法从根本上避免漏同步。向插件注入整包应用 CSS 或克隆宿主组件则会带入页面布局、框架实现和无关选择器，容易影响作者页面。共同的原生 CSS 保留较小边界，并允许作者通过普通 CSS 明确覆盖；原生控件与 React / Radix 的语义适配仍由各自入口承担。

## 材质与覆盖边界

透明只用于布局、留白和内容装饰。含字面板、输入、菜单与代码阅读区按用途保留阅读保护，强调按钮和状态图形保留成对语义色。100% 表示壁纸本身完整显现，不能解释为所有前景控件同时没有底色。普通容器不统一添加大面积模糊，必要的叶子控件和覆盖面板才使用局部磨砂。

共同规则放在 `starter-defaults` 层：宿主布局与调用方 utility 可以定制，插件作者未分层 CSS 同样优先。作者设置独立背景、绘图或第三方组件样式时，须负责自己的文字和底色对比。Canvas / SVG 内容、自绘结构、操作系统子弹窗和未注册 ShadowRoot 不可能仅靠标准元素样式自动推断；这类内容显式接入材质或保留内容专用配色。

## 影响与失败路径

新增样式文本属于当前宿主与随包 SDK 的主题快照，不改变 Rust DTO、原生权限、sandbox、CSP、设置或存档格式。CSS 来自可信安装包，不接受插件回写宿主 CSS，也不引入远程样式资源。共享源更新随下一份主题快照生效；普通字段编辑沿用主题引用，不重复复制整份样式和字体。首帧继续在完成主题与绘制握手后展示。

主题变量从计算后的根元素自动收集，过滤实现内部变量，避免新增材质时再次维护名字清单。公开控件的新语义 slot 需接入共同规则或显式说明继承 / 内容专用材质，静态门禁保护这一边界。方案由本轮需求与自审确定，没有将自动化评审冒充维护者审批。

## 验证与复查

回归须覆盖宿主、iframe、注册 ShadowRoot 的相同规则、主题更新与后插入控件；作者 CSS 仍优先。深浅主题同时验证 0%、中间档和 100%，以最终绘制像素及文字对比度检查裸正文、导航、输入、选中态、表头和语法色，而非只比较 token 数字。真实 WebView 的平台弹窗与正式安装版仍按[桌面验证边界](../testing.md#避免干扰本机桌面)单独验收。

若今后需要向不随宿主发布的独立客户端提供整套组件协议、开放第三方运行时样式源，或无法继续使用原生 CSS 层级与语义结构，应重新评估共享边界和版本协商，而不是继续增加宿主 / SDK 的两套手工映射。
