# 8. 使用声明式视图展示扩展应用

- 状态：被 0009 取代（固定模态与视图数据权限限制；其他运行时约束继续有效）
- 日期：2026-10-23
- 决策依据：用户要求扩展以图标卡片打开，并提供计算器、小游戏等默认示例；继续保持单一 Extism 运行时
- 影响模块：扩展清单、IPC、扩展中心、独立示例构建；本次由编码智能体自审，不代表第二位维护者审批
- 相关：[ADR 0007](./0007-extism-extensions.md)、[扩展指南](../extensions.md)

## 问题、方案与验收

文本命令没有应用界面。为每个示例在 React 中硬编码算法会使第三方无法复用；执行第三方 HTML 又需要额外网页容器、资源分发和消息桥。因此沿用 Extism，只增加一个有版本的声明式视图协议：插件返回显示文本、字段、按钮组和不透明状态；宿主渲染现有 UI 组件，点击时把状态与字段交回插件。计算器和双人井字棋的规则都在真实 Rust PDK 插件中。

验收包括图标卡片、直接体验两个内置示例、第三方同协议视图、键盘操作、输入与失败结果保留、请求串行、取消等待和实际 Wasm 往返。实时画布、任意 DOM 和常驻游戏循环暂不提供，需要此类交互时重新评审视图方案。

## 契约、权限与失败路径

清单增加可选的受限图标与 `view` 结果类型。视图要求 JSON 输入且无文件 / 网络 / 文本授权，独立 IPC 只接收本视图的动作、字段、状态和语言。输入输出均在 Rust 校验数量、长度、标识符、版本和总大小；按钮不包含脚本、URL、样式或命令。每次交互沿用原有独占租约、内容哈希、执行预算、取消和退出等待，错误保留上次界面，不自动重试有状态动作。

内置卡片始终可见，点击体验才把随应用附带的无权限包安装并启用；此行为在入口说明。外部包仍需审阅和确认信任。内置包启用前核对完整清单和模块哈希；已有同 ID 的不同包不被替换或自动信任。安装和启用分别受 revision 约束，后一步失败时保留已安装的禁用项并提示错误。

视图状态只属于当前会话，可导出，关闭应用视图明确结束会话；离页 / 退出协商登记未保存工作并保留回调。关闭或卸载时请求取消，直到实际停止才结束会话。

连续按钮交互的实际模块测试发现逐次编译明显拖慢输入，因此使用 Extism 自带的 `CompiledPlugin`，进程内只保留最近一个编译模块，以真实模块哈希和预算匹配。继续逐次新建实例，不共享插件变量；SDK engine / 小型实例池串行使用。代价是进程在两次调用之间保留一份编译代码和引擎，磁盘编译缓存仍关闭。验收同时检查状态隔离与更低 fuel 预算不会被旧编译结果覆盖。

## 兼容、分发与验证

原有格式 2 / API 1 文本、JSON、Markdown 包保持原样；图标缺省使用拼图，注册表 schema 2 无迁移。旧宿主会拒绝新的 `view` 枚举，不会误执行为文本命令。设置、数据库、CSP 和 WebView capability 不变。

两个示例共用一个 Rust PDK 模块，预编译为随源码提交的分发资源；保留源码、锁文件和重建 / 一致性检查脚本，常规应用构建不增加 Wasm 交叉编译前置条件或新的运行依赖。Rust 测试直接执行随包模块，CI 使用 `pnpm extension:demos:check --rebuild` 重建并比较已提交的 Wasm，快速哈希回执检查不代替编译比对。浏览器仅说明原生运行限制，不伪造插件执行。

验证以相关前端行为、Rust 边界和真实模块测试、生成绑定、构建与无头界面检查为准。正式安装器、真实 WebView 和其他操作系统仍需对应环境验收；失败不删除用户注册表或文件。
