# 7. 通过 Extism 接入跨语言 Wasm 扩展

- 状态：被 0011 取代（包协议、进程内执行与单运行调度；单一 Extism 技术选择继续沿用）
- 日期：2026-10-23
- 决策依据：用户要求复用通用框架，并明确允许替换未发布的原生程序扩展，避免并行维护两套运行机制
- 相关：[ADR 0011](./0011-capability-extension-host.md)、[扩展指南](../extensions.md)、[架构说明](../architecture.md)、[ADR 0006](./0006-native-process-extensions.md)

## 范围与方案比较

影响扩展包、注册表、IPC、命令面板和运行生命周期。采用 Extism 的 Rust SDK，在阻塞线程运行标准 Extism Wasm 模块；删除原生进程执行器、专用进程 SDK 和系统命令示例。保留已有条件写入、默认禁用、授权、独占运行、停止及退出等待机制。

| 方案                    | 优点                                                       | 代价                                                        |
| ----------------------- | ---------------------------------------------------------- | ----------------------------------------------------------- |
| 独立 Node 宿主          | 完整 JS 生态、异步 I/O                                     | 额外分发运行时；Rust 插件仍需进程桥接                       |
| 浏览器 Worker 内的 Wasm | 不引入原生 JIT                                             | 执行生命周期跨前端和 Rust，窗口关闭、更新和多窗口占用更复杂 |
| Extism Rust SDK         | 统一跨语言插件 ABI、资源控制和取消；直接沿用 Rust 生命周期 | 增加 Wasmtime 的包体与首次编译成本                          |

## 契约与边界

使用包格式 2 和注册表 schema 2。此前格式 1 是本分支的未发布原型，不提供原生兼容通道；遇到已有格式 1 或未来存档明确拒写，保留原件，不执行或删除旧程序。应用设置、数据库和文件数据不迁移。

安装包仅包装元数据与 Wasm 内容，不自创 Wasm ABI。命令声明直接映射到模块导出函数；文本输入模式允许使用未适配本项目的 Extism 插件，JSON 模式接收本次用户明确选择的文本、文件和 broker 响应。返回值统一为有界 UTF-8，按声明展示文本、JSON 或安全 Markdown。动态命令复用 CommandsProvider，执行入口打开扩展工具并要求用户手动运行，不自动发送数据。

为兼容 JS PDK 启用无预开目录、无继承环境的基础 WASI；拒绝阻塞 polling，禁用直接 HTTP 和模块远程下载，不提供任意文件路径或系统命令宿主函数。外部能力只通过现有的本次文件选择和 HTTPS broker 交付；声明用途需逐项授权。Wasm 每次新建实例，不持久保存插件内部变量；设置内存、fuel 和执行超时，取消时等待实际运行结束后释放租约。编译阶段在阻塞线程进行，不宣称执行时限覆盖 JIT 编译。

界面只复用既有安全 Markdown 和文本组件，不执行扩展返回的 HTML / JS，不开放主页面 DOM。完整 Node API、常驻后台服务和自定义网页面板不在本次范围，后续按真实需求新增公开能力。

## 依赖与分发

Extism 1.41.0 使用 BSD-3-Clause；Wasmtime 49.0.4 使用 Apache-2.0 WITH LLVM-exception，以锁文件核对完整传递依赖。关闭 Extism 默认 feature，去掉文件 / HTTP 注册和 HTTP 客户端；保留其必需的 Wasmtime 编译与运行组件。不增加前端运行时依赖、WebView capability 或 CSP 来源。Rust PDK 与 JS / TS PDK 只用于独立示例，不进入宿主依赖图。安装器资源和便携目录保留第三方许可原文，并测量原生包体与编译成本；浏览器分块大小用既有构建检查。

## 验收与恢复

验证安装默认禁用、revision、授权、升级撤权、存档保护、运行内容哈希、取消、执行时限、内存额度和退出占用。用未修改的外部 Extism 模块验证通用调用，用 Rust 和 JS / TS 开发示例验证实际构建往返。前端检查动态命令注册 / 撤销、输入保留、安全结果展示和晚到订阅清理；无头浏览器检查演示限制。正式安装版、多窗口和其他操作系统另行验收，不能以 CI 配置代替实测。

若后续需要完整 Node API、长驻任务或任意系统调用，应重新比较单一宿主方案及其成本，不恢复两套重复的安装与授权体系。

后续应用图标与声明式视图、单模块内存编译复用由 [ADR 0008](./0008-extension-app-views.md) 补充，继续沿用本记录的单一 Extism 运行时和隔离边界。
