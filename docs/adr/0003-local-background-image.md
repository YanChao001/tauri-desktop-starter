# 3. 将压缩背景图片纳入有界设置快照

- 状态：被 [0004](./0004-wallpaper-library.md) 取代（当前选中图片仍保留自包含设置快照）
- 日期：2026-10-21
- 相关：[设置架构](../architecture.md#状态管理与设置迁移)、[界面规范](../conventions/ui-guidelines.md#外观设置)

## 背景

用户需要导入自己的背景图片，并在应用重启和多窗口中保留选择。桌面以原生设置快照为权威，浏览器演示使用独立 localStorage；设置已有原子替换、revision 冲突处理、未来 schema 拒写和 128KiB 总量限制。

## 备选方案

| 方案                                  | 收益                                 | 代价                                                       |
| ------------------------------------- | ------------------------------------ | ---------------------------------------------------------- |
| 原图写入独立资产目录，设置保存资源 ID | 保留画质，适合图库                   | 需要原生资源授权、图片与设置的两阶段提交，以及孤立文件回收 |
| IndexedDB 保存原图                    | 浏览器有较大空间                     | 需要另建桌面权威来源、跨窗口同步与恢复规则                 |
| 压缩栅格图随设置保存                  | 复用已有原子快照、CAS 与双环境持久化 | 仅保存一张优化后的图片，修改偏好时快照也会携带图片         |

## 决策

采用第三种方案。通过用户选择的 File 在本机解码、缩放和重编码，仅保存一张最长边不超过 1600px、data URL 不超过 96KiB 的静态 WebP / JPEG，以及名称和填充方式。拒绝远端 URL、文件路径、SVG、过大或不可解码的输入；原始文件不修改。Rust 重新校验保存格式、大小、名称和图片头，不依赖前端校验建立存储边界。

设置 schema 使用 3；无版本存档和 schema 1 / 2 迁移时保留已有偏好。可读取 schema 2 的旧前端会把 schema 3 视为未来结构并阻止自动写回。回退时使用能读取该格式的应用，或明确重置偏好；不能假定旧版本会保留导入图片。

导入或保存失败时保留此前的背景和用户修改，沿用错误与重试入口。切换内置皮肤保留导入图片；移除图片或重置偏好才清除设置中的副本。组件卸载后不应用晚到的导入结果，期间切换背景也不能被旧导入覆盖。不新增 IPC、插件权限、CSP 来源或依赖。

## 后果与验证

图片会被压缩，不是原图图库，也不保存动画或元数据。选择 10MiB / 4000 万像素以内的输入；超过保存预算时继续降低质量与尺寸，仍不能满足则提示更换或缩小图片。浏览器原图解码的资源消耗仍受运行时约束。

验证覆盖旧设置迁移、危险格式 / 超限输入拒绝、失败不替换快照、revision 同步、导入 / 替换 / 移除、卸载和并发选择、刷新 / 进程重启恢复，以及明暗 / 高对比度下的可读性。正式目标平台验收范围按实际测试报告，不由代码存在推导。

## 复查条件

需要多图图库、保留原始画质、动画或跨设备同步时重新评估独立资产存储；不放宽现有设置上限来容纳原图。
