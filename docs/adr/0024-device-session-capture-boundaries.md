# 24. 将设备会话与记录回放独立于插件页面

- 状态：已采纳
- 日期：2026-10-30
- 决策者：维护者授权按里程碑重构；实施保留自审与独立检查，不虚构第二位人类审批人
- 相关：[实施计划](../plans/device-workbench-foundation.md)、[架构说明](../architecture.md)、[扩展指南](../extensions.md)

## 背景

基座将演进为功能可组合、可按需交付的桌面助手，串口工作台是明确需求。现有 Wasm 命令与隔离 HTML 足以支持小应用，但设备连接、持续字节流、多个显示视图、记录与自动化不能由某个 iframe 或一次短任务持有。

串口的重连、控制线、发送与烧录具有物理副作用；日志缓冲、原生驱动与磁盘有独立失败场景。“延长调用超时”“保持所有页面存活”或“每个功能单独开端口”无法建立统一的资源所有权与恢复语义。

## 备选方案

| 方案                                       | 收益                                         | 代价与结论                                                     |
| ------------------------------------------ | -------------------------------------------- | -------------------------------------------------------------- |
| 继续由每个插件独立管理连接和数据           | 不改变现有契约，单插件开发快                 | 重复连接、记录与仲裁，多视图和撤权难协调，不作为工作台公共基础 |
| 全面切换 Node／同页组件插件                | 可复用部分包生态和 UI 组件                   | 改变不可信代码与 DOM 边界，增加运行时与原生依赖成本，不采用    |
| 立即建设多进程微内核与通用总线             | 服务和交付边界最自由                         | 尚无真实使用验证，版本、监督与发布复杂度过高，暂不采用         |
| 模块化领域内核＋现有受限插件，按需再拆进程 | 保留安全与分发机制，先验证真实设备／回放契约 | 需要新的会话、数据与记录模型，采用                             |

## 决策

在当前 Rust crate 中增加不依赖 Tauri 与界面的设备领域模块，并将记录／回放作为独立模块。先用虚拟输入和无头 CLI 形成可运行闭环，再接真实串口、原生授权和工作台。

- 会话持有业务状态与连接代次，显示只持读取游标与局部交互；显示生命周期不隐式改变设备会话。
- 字节保持二进制，控制请求和有限数据批次分开。序号、方向、时间来源、偏移与缺口可追踪；有限内存不承诺任意过载无损。
- 接收、写入和参数修改由领域服务协调；重连使旧连接操作和未执行写入失效，不自动重发危险命令。
- 记录模块只依赖设备公开事件模型，不反向被设备调用；回放是只读源，不具备真实输出能力。
- 普通 Wasm 保持单次新实例和现有预算。持续解析先用批次与显式有界状态，必要时再引入可监督会话 actor，不能占死短任务槽。
- 安装信任、授权、generation／revision、窗口 epoch、CSP、恢复和未来数据拒写继续保留。模块内部句柄不是用户授权；公开给前端或插件前须另做边界设计。
- 默认业务可以使用同一领域契约，不要求所有模块对应同一种插件、一个进程或一个分发包。原生 provider 属于另一信任等级，不能宣称拥有 Wasm 沙箱。

当前实现与额度在相应模块指南维护，里程碑和范围在实施计划维护；本 ADR 不作为逐项交付记录。

## 后果

领域规则可在没有 React、Tauri 窗口或真实硬件的条件下测试，记录与回放为协议回归提供确定性输入。一个设备连接可以自然支持多个视图，后续拆分 provider 不必先推翻现有受控插件。

新增事件、会话与文件格式会增加概念和测试成本。当前 crate 仍链接桌面依赖，模块独立不等于编译或安装体积独立。首批不提供后台守护进程、真实串口、原生流式 IPC 或可下载执行器，不得用虚拟成功冒充硬件验收。

对外稳定前可按当前契约更新所有调用方，不为开发快照保留未承诺兼容层；未知文件版本、原始数据保留及失败恢复保护不因此移除。

## 复查条件

领域模块持续依赖桌面状态、CLI 被宿主链接成本阻塞，或需要独立后台、厂商 SDK 隔离与实际按需减重时，评估拆 crate／sidecar。真正出现跨插件协议复用、性能瓶颈或外部作者需求时，再设计稳定 provider 协议、会话 actor 和兼容窗口，不预建万能总线。
