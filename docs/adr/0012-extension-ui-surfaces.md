# 12. 区分通用工具视图与插件自定义界面

- 状态：已采纳
- 日期：2026-10-25
- 决策者：维护者要求实施；本次保留自审与分层验证，不虚构第二位审批人
- 相关：[扩展指南](../extensions.md)、[0011](./0011-capability-extension-host.md)

## 背景

2048、数织和故事骰子已暴露现有界面的边界。`fields/groups/blocks` 把字段排在按钮前，再把内容放到另一列，插件不能自然地组合相关内容与操作。2048 的种子比棋盘更靠前、方向操作没有按键声明；故事骰子的锁定框与灵感分离，草稿与参数争夺空间。增加控件类型并未解决布局和交互组织问题。

宿主还混合了业务与管理：重复标题、显眼的导入控件、常驻停止按钮，以及直接清空进度的结束操作。无溢出、可 Tab 遍历和协议测试通过，只证明局部约束，不能证明工作流合用。Wasm 能力隔离与 UI 呈现属于不同边界；文件、网络和存储授权不应承担布局限制的职责。

## 备选方案

| 方案                          | 收益                                       | 成本与限制                                         |
| ----------------------------- | ------------------------------------------ | -------------------------------------------------- |
| 持续扩充固定视图              | 简单工具低成本，复用主题与控件             | 仍难组织复杂应用，容易添加针对样例的特殊字段       |
| 通用 JSON 组件树与事件语言    | 可表达嵌套布局                             | 逐渐维护另一套前端框架和布局语言，不作为默认方向   |
| 通用视图加隔离的本地自定义 UI | 简单工具保持低成本，复杂应用按业务组织界面 | 增加资源分发、隔离、消息桥和生命周期，需要独立验证 |
| 所有插件改成网页              | 表达自由度统一                             | 简单文本命令也承担前端构建成本，不采用             |

参考 [VS Code Webview API](https://code.visualstudio.com/api/extension-guides/webview)：标准宿主能力不足时允许自定义 HTML 与消息通信，同时评估资源成本。借鉴两类界面的分工，不复制其 Node 运行环境。

## 建议方向

保留通用工具视图，增加可选的本地自定义 UI。具体边界按下文“本次实施范围与验收边界”落地；0011 中仅声明式 UI 的限制由本 ADR 部分替代，Wasm 与能力 broker 的边界保留。

- 简单命令与表单继续输出文本或 JSON。复杂应用可交付本地 HTML / CSS / JavaScript，作者选择框架或普通 DOM，Wasm 可继续承担业务规则；源码语言不带来额外权限。
- 宿主负责入口、权限、错误边界和必要工具，插件负责业务布局、局部交互与草稿语义。主题用有限 CSS token 注入，不能访问宿主 DOM。
- 权限缺失时在相关操作附近解释用途并提供管理入口，避免留下无说明的禁用按钮。
- 无副作用的高频 UI 交互留在 UI 上下文，不为每次展开面板或移动焦点重建 Wasm；需要宿主能力时使用有界消息桥。
- 插件明确报告未保存工作并提供保存 / 放弃回调，不把任意按钮动作永久当作未保存，也不把导出 JSON 会话当作所有插件的业务保存。

## 隔离、兼容与恢复

采用无同源权限的 sandbox frame，分层验证初始化脚本、IPC 注入、资源 origin、进程与线程行为及卡死恢复。不能仅添加 iframe 就宣称完成隔离，也不将 UI 上下文称为新的操作系统权限沙箱。

资源随包交付，限制文件数与总字节，校验路径、重名、编码及哈希，签名覆盖完整资源。默认不加载远程入口或脚本；CSP 限制直接网络、导航、弹窗与执行来源，网络和文件仍走授权 broker。文档通过清单引用和受校验的 uiDocuments 交付，不能绕开资源服务直接注入宿主。

消息桥按界面实例和安装代次绑定，核对来源，限制方法、参数、频率、字节和在途数量。不接受自述授权、任意 `invoke`、宿主对象或路径；禁用、替换、关闭与卸载使旧端口失效。取消不撤回已经发生的外部副作用。

明确会话草稿、持久保存、暂离保留与崩溃恢复的语义。KV、凭据和原始数据保留现有隔离与未来版本拒写保护。开发阶段可以更新协议，但不能让旧宿主误执行新资源或以删除原始数据恢复。

## 分步验收

1. 先修复工具拥挤、焦点丢失、不可操作元素语义及结束时的数据保护，独立提交，不改包与存档协议。
2. 用一个真实插件试点自定义 UI，先验证资源隔离和消息桥，再开放业务能力；覆盖主题、键盘、错误、关闭、取消与未保存工作。普通声明式插件无需改写。
3. 按真实任务重做样例：主操作在首屏、参数按频率组织、锁定贴近内容、创作区获得主要空间。2048 验证方向键、触屏与延迟，不只验证按钮可点击。
4. Rust 边界、绑定、SDK、市场打包 / 签名和样例配套验证后再发布。区分无头浏览器、原生服务与正式安装版；目标平台隔离与 WebView 交互未验收前不声称完整支持。

本决策采纳不等于全部平台验收通过；实际实现与预算由扩展指南维护，分层验证与未测范围随交付说明。

## 本次实施范围与验收边界

选择无同源权限的 sandbox frame。每个视图命令可声明本地文档 ID；包交付对应的单文件 HTML（CSS、JavaScript 和图片内嵌，框架可先构建为单文件）。采用文件级 UI 入口，避免再维护通用布局语言和任意目录资源服务器。Wasm API 和通用视图继续使用现有版本；UI 元数据作为包格式 3 的可选扩展，旧宿主因未知字段拒绝新包，新宿主不重建已有 schema 3 注册表。

原生校验文档数量、UTF-8 字节数、引用与内容哈希，以哈希命名缓存，不接受插件路径。目录签名覆盖完整包，目录预览还绑定文档 ID、字节数与哈希。文档单个最多 512 KiB、每包合计 2 MiB、最多 32 份，独立缓存上限 64 MiB。损坏资源拒绝打开，旧包回退同时校验 UI；不删除原始注册表或私有数据。

原生专用协议按不可预测令牌和宿主窗口发放一次界面租约；读取时重新校验安装代次、启用状态、命令授权与内容哈希。原生通过 Tauri 的自定义传输入口，仅向顶层 frame 安装带密钥 IPC，不能依赖 WebView2 忽略 main-frame-only 脚本。保持上游传输与序列化，记录 Tauri 许可；全 frame 文档启动脚本在作者代码前锁定 WebRTC，并仅向专用资源文档安装 SDK。正常解析完整作者 HTML，不自建 HTML 模板渲染器或脚本加载器。框架标题栏和可用 Tauri IPC 留在可信主 frame；子 frame 只获 allow-scripts，不获同源、顶层导航、弹窗、下载或表单权限。独立响应 CSP 禁止网络、外部脚本、子 frame、worker 和表单，允许包内的内联脚本与样式；宿主 CSP 只增加指定 frame 来源，不放开宿主内联脚本。

受控 MessagePort 按具体 frame 实例连接。桥只支持获取视图、编辑字段、运行动作、保存已生成产物和更新本窗口草稿检查点；不传入原生命令名、安装身份或路径。宿主限制包大小、频率、在途调用和请求序号。卸载、禁用、替换、关闭、离页使旧端口失效；每次实际能力调用仍由 Rust 复核当前安装身份及授权。高频局部动画和布局不调用 Wasm。

插件通过检查点明确报告草稿是否未保存。暂离保留本窗口状态；通用“保存”导出完整会话快照，插件的业务保存由它自己的按钮实现，二者不混淆。导入绑定 UI 哈希，文件仍需重选，凭据不导出。取消继续遵循现有合作语义，不声称回滚已落盘结果。

宿主管理入口复用所在窗口的 chrome，不在业务正文重复绘制图标、扩展名和工具行：嵌入页使用导航上下文右侧工具入口，独立窗口使用自定义标题栏中的清单图标及主题 / 工具 / 窗口控制，不增加独立窗口搜索或修改操作系统窗口图标。长说明收进可聚焦的帮助提示，保留紧凑面板；当前入口与时序由扩展指南维护。

首屏加载按资源、视图和 SDK 首轮呈现的真实状态显示骨架，保持子文档可测量；SDK 应用主题并获得 DOM 绘制机会后再展示内容，不人为延长加载，也不在后续业务忙碌时重新隐藏已经可用的界面。这是呈现握手，不放宽 sandbox、CSP、消息桥或原生能力。

验收包括 Rust 资源 / 租约 / 撤权检查、桥的伪造消息与预算回归、真实 Wasm 业务 fixture、无头浏览器中的主题 / 键盘 / 布局 / CSP 和关闭草稿流程。iframe 不作为操作系统级隔离，UI 死循环的进程资源隔离和真实 Windows / macOS / Linux WebView 验收不由浏览器替代；未实测平台会在交付中明确列出。
