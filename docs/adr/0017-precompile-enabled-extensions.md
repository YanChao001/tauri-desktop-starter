# 17. 启用时预编译并保持独立执行实例

- 状态：已采纳
- 补充：命令预算的预编译档位由 [0019](./0019-bounded-extension-compute.md) 约定；本记录的仅编译、独立实例与有界缓存结论继续有效。
- 日期：2026-10-27
- 决策者：维护者要求将编译前移到启用阶段；按资源、并发、失败与兼容边界自审，不虚构第二位审批人
- 相关：[架构说明](../architecture.md#页面与演示边界)、[扩展指南](../extensions.md#执行存储与生命周期)、[0011](./0011-capability-extension-host.md)、[0016](./0016-retain-extension-surfaces.md)、[测试规范](../testing.md#rust-测试)

## 背景

有界保留插件页面可减少回访时的文档重建，不能消除首次打开的 Wasm 运行时编译。包校验已经检查 ABI、导出和资源，但其验证结果不等同于 Extism 运行缓存；应用重启或 worker 回收也会丢失内存中的编译结果。将“已经安装并启用”理解成“首次调用已准备好”，会继续让用户在打开业务页面时承担明显等待。

维护者明确要求在启用时完成编译。提前编译与提前执行具有不同的安全和状态语义：插件的 start、初始化及导出可能失败或产生业务请求，不能为优化首开而运行这些阶段。实际调用仍须获得当次身份、窗口和权限租约，并保持每次独立实例的隔离。

## 备选方案

| 方案                             | 收益                                           | 成本与限制                                                                          |
| -------------------------------- | ---------------------------------------------- | ----------------------------------------------------------------------------------- |
| 首次调用时编译，沿用现有 LRU     | 实现和启动工作量最少                           | 首次进入插件仍等待编译，页面保留不能解决重启后的冷路径                              |
| 持久化 JIT 编译结果到磁盘        | 可跨进程复用部分编译工作                       | 增加编译器 / 平台兼容、缓存完整性、失效与分发恢复边界；当前没有相应证据，不采用     |
| 预先创建实例或运行初始化         | 可继续前移实例创建成本                         | 会触发插件 start / 初始化，实例内存与业务状态需另行管理，违背仅编译与独立调用的边界 |
| 启用前仅编译，重启后有界后台预热 | 将主要编译等待前移，复用现有 worker 和编译缓存 | 启用操作增加等待；后台消耗有限编译资源，缓存淘汰后仍可能冷编译，采用                |

## 决策

为固定 worker 协议增加内部 `Prepare` 操作，只调用 `CompilationCache.compile` 填充运行时编译缓存；不调用 `new_from_compiled`、不创建实例，不执行 Wasm start / 初始化或任何导出，不运行效果 broker。包验证仍负责 ABI / 声明导出的检查，Prepare 成功不表示后续初始化或业务动作一定成功。

启用、安装并启用及升级并启用在提交启用状态前完成 Prepare。原生先在短暂注册表临界区核对候选包、信任、授权和 revision，登记内部 RunLease；随后释放锁，在有界调度与 worker 中编译。完成并释放租约后重新获取锁，按原 revision 和安装身份复核，再执行原子写入。编译失败、取消或期间出现管理冲突时，保留原安装、启用状态与授权，不以“已编译”为理由覆盖更新的注册表。

预览与不启用的安装继续沿用现有包校验，不额外触发启用预热；编译工作不与包安装、命令执行或业务保存混为一谈。实际打开应用视图才调用初始化入口。

应用启动后，各窗口 ExtensionsProvider 首次成功接受列表时检查一次；当时已有启用扩展才在后台调用宿主无参 `prepare_enabled_extensions`，不等待预热才渲染路由，后续列表刷新不重复触发。原生读取当前已启用安装，优先选含视图命令的最多 4 项，逐项校验哈希和当前身份后 Prepare；同一轮多窗口并发请求合并并共享结果，结束后显式请求可重新执行。启动预热不重新登记内置包、不重放业务命令，也不接受前端指定的模块、路径或安装身份。

预热复用既有最多 2 个 worker 的池，不新增专用进程或固定暖槽。内部预编译 owner 同一时刻最多执行一项；每个 worker 保留最多 4 条 / 合计 32 MiB 源模块的编译 LRU，实际 Run 优先选择已缓存目标哈希的空闲 worker。目标缓存所在 worker 忙碌时可用其他空闲槽，不将前台运行固定到一个 worker。缓存只保留编译代码，每次真实调用仍创建新实例，线性内存、全局变量和 WASI 状态不跨调用共享。

## 并发、取消与失败

预编译进入原有有界执行队列和 15 秒单项总预算，内部活动租约参与暂停、撤权、停用、替换、退出及实际结束等待；不伪造真实窗口标签，也不暴露为普通插件窗口的运行状态。后台启动预热优先级低于前台运行和显式启用，执行位不足时让位并取消后台工作，实际 worker 结束后才释放位置。显式启用仍按用户正在等待的前台操作处理。

启动预热的合作取消停止该轮，不改变启用状态，也不自动循环重试；此前没有真实错误时正常返回，已发生的真实错误仍汇总为可重试失败。模块损坏、编译失败等真正错误由宿主 toast 提供显式重试；用户也可直接打开插件走普通运行路径。多个窗口仅合并正在进行的同一轮，不能把一次成功当作永久有效的准备凭据。

启动预热逐项复核当前 id、哈希、generation 与启用状态；无关插件推进全局 revision 不应使这项只读准备失败。启用 / 安装的最终写入仍严格遵循原 revision CAS。缓存命中从不替代每次运行的启用、安装身份、权限、窗口和租约检查；撤权后即使编译代码仍在内存，也不能继续取得业务执行资格。

## 兼容与资源代价

新增的是宿主启动准备 IPC 与内部 worker 操作，不增加插件权限、SDK 作者方法、Wasm API 或包格式，也不放宽网络、CSP 或 sandbox。生成绑定和原生门面随宿主同步；旧插件仍使用原命令和会话协议，本地工作台的 Wasm 会话保持 schema 3。页面保留继续按 [0016](./0016-retain-extension-surfaces.md) 管理，编译预热不改变其结论。

启用会承担原先延后到首开的编译时间；后台预热占用有限 CPU 与内存，JIT 实际分配不等于源模块字节预算。最多选 4 项也不保证它们始终全部留在同一 worker：源字节上限、其他调用、worker 崩溃、取消回收及 LRU 都可能使代码失效。应用退出不保存编译结果，不写入磁盘 JIT 缓存；磁盘模块内容缓存只保存已校验模块，并不等于可跨重启运行的编译产物。

导航 JavaScript 预载、保留 iframe、worker 编译缓存和磁盘模块缓存有各自的触发与淘汰。预热完成前、未选中的插件或淘汰后的调用仍可能编译，不能承诺所有已启用插件首开都没有等待，也不把某个浏览器 fixture 的时间当作原生安装版性能。

## 验证与复查

回归应使用包含陷阱 start 的模块证明 Prepare 成功而实际 Run 初始化失败，使用可变全局计数器证明预热后每次实例仍独立，并验证坏模块预热失败后 worker 可以继续处理正常请求。真实 worker 协议检查与进程内单测分别验证，不互相替代。

存储和调度覆盖启用 / 安装预编译失败保留原值、编译期间 revision 冲突、启动并发合并和显式重试、预算选取、前台让位、停用 / 撤权 / 替换取消，以及暂停和退出等待实际结束。前端覆盖启动请求不阻塞列表、不因快照刷新重复启动、失败后显式重试和旧结果不改写新状态；绑定与门面核对新增无参 IPC。具体命令和检查范围由 [测试规范](../testing.md#rust-测试) 维护。

本记录表示方案已采纳，实际测试结果随交付说明；不据此宣称正式安装版、跨平台 WebView、目标签名构建或启动性能已经验收。性能采样须区分编译预热完成前后、已编译首开、保留页面返回和淘汰后重建，并在同一设备、版本与数据条件下比较。

当启用等待影响可用性、后台编译显著增加启动负担、前台仍被抢占拖慢，或大量启用插件持续超出缓存预算时，重新评估触发时机、优先级和选择范围。若需要跨重启的原生编译缓存，须另行审查平台 / 编译器兼容、缓存完整性及恢复方案；不能通过复用有状态实例或提前执行业务来延伸本决策。
