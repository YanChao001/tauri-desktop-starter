# 安全规范

本文说明 IPC、权限、更新和本地数据的安全边界。桌面代码运行在用户机器上，不应将随包配置或前端代码当作秘密存储。

## 攻击面

| 面               | 风险                             | 主要防线                                        |
| ---------------- | -------------------------------- | ----------------------------------------------- |
| WebView 里的内容 | XSS → 拿到 IPC 调用能力          | CSP、不使用 `dangerouslySetInnerHTML`、外链隔离 |
| IPC 命令         | 参数未校验导致路径穿越、命令注入 | Rust 侧校验入参                                 |
| 能力声明         | 权限开太大，前端被攻破即失守     | capabilities 最小化                             |
| 依赖             | 供应链投毒                       | 锁文件、审计、来源审查                          |
| 更新通道         | 中间人替换安装包                 | 签名校验 + HTTPS                                |
| 本地数据         | 明文存储敏感信息                 | 系统钥匙串、按需加密                            |

## 能力最小化

`src-tauri/capabilities/default.json` 是 Tauri 核心与插件命令的**白名单**，未授予的能力默认拒绝。

自定义 Rust 命令另有规则：本项目没有启用应用命令 ACL，`bindings.rs` 注册的命令默认可由本地应用前端调用。需要按窗口限制自定义命令时，先通过 `tauri_build::AppManifest::commands` 定义应用 ACL，再声明权限并分配到 capability。入参校验始终放在命令内部，生成 TypeScript 不替代运行时校验。

完整权限列表以 [`default.json`](../src-tauri/capabilities/default.json) 为准：权限仅分配给 `main` / `secondary`，没有远程页面 capability。当前直接开放给前端的插件能力包括：

| 能力           | 范围与用途                                                                   |
| -------------- | ---------------------------------------------------------------------------- |
| 窗口及核心能力 | 标题栏、窗口显示和既有核心 API                                               |
| 通知           | 查询 / 请求系统授权、发送通知和接收点击；后台任务通知不主动弹授权请求        |
| 剪贴板         | 用户主动读取 / 写入文本，没有后台监听                                        |
| 全局快捷键     | 登记、检查和释放；门面再限制演示组合，插件 capability 本身不限制组合         |
| HTTP           | 仅 `httpbin.org` 与 `jsonplaceholder.typicode.com`，重定向目标继续检查 scope |
| opener         | `http(s)` URL 交给系统浏览器，不在可信 WebView 载入远程网页                  |

原生 dialog、目录定位、数据库、更新、凭据、自启动和固定 worker 由 Rust 服务调用；未向前端开放通用文件、任意 Shell、SQL 或 updater 插件命令。注册插件不等于授予其全部前端权限；Rust 服务直接使用插件的能力仍需在自定义命令内校验。窗口状态由 Rust 插件自动管理。自定义命令规则参考 [Tauri 应用命令权限](https://v2.tauri.app/security/capabilities/)。

测试 WebDriver 仅由可选 `e2e` feature 编译，额外权限与全局 Tauri API 只放在测试 overlay；启动还要求独立 `.e2e` 标识及绝对临时数据目录。原生设置 / 数据库始终使用临时目录，Windows / Linux WebView 使用临时数据目录，macOS 测试 WebView 使用非持久 incognito 存储。正式配置不注册测试服务；隔离方式见 [真实桌面 E2E](./testing.md#真实桌面-e2e)。

规则：

- 一个权限一个理由。加之前先问：不加会怎样？能不能在 Rust 侧代劳？
- 不要用 `core:all` 或通配符图省事。
- 按窗口分配权限。如果以后加了「预览窗口」展示外部内容，它不应该有文件系统权限。
- 每季度复查一次，删掉不再需要的权限。

## CSP

生产规则在 [`tauri.conf.json > app.security`](../src-tauri/tauri.conf.json)，限制脚本、字体、图片与网络来源；新增资源来源时在同一提交调整并验证。

说明：

- `style-src 'unsafe-inline'` 是必需的：Radix 的浮层组件通过 `style` 属性做定位。
- `connect-src` 里保留 `ipc:` 与 `http://ipc.localhost`，否则 `invoke` 会被拦。
- `devCsp: null` 表示开发构建 **回退到生产 `csp`**（Tauri 源码 `AppManager::csp()`）。该规则用于 Tauri 提供的本地应用资源；Windows 的本地资源地址可能显示为 `http://tauri.localhost`，不能仅按 `tauri://` 字面判断。`pnpm app:dev` 则从 Vite dev server 加载外部 URL，开发时能加载资源不能证明正式包的 CSP 正确。
- 改成加载本地 `dist` 时应重新验证 CSP；构建产物本身不使用 Vite HMR。若另行接入开发资源，按实际地址配置 `devCsp`，不要预先放开固定 WebSocket 端口。
- 需要访问外部 API 时，在 `connect-src` 里精确列出域名，不要写 `*`。
- 当前只允许指定的两个 HTTPS 演示域名和 `wss://echo.websocket.events`；WSS 使用标准 WebSocket，门面检查协议、主机和消息大小。浏览器同源策略、桌面 CSP 与原生 HTTP 插件 scope 是不同边界，不能互相替代。
- 图片允许本地资源、`data:` / `blob:`，媒体仅允许本地和 `blob:`，用于用户明确选择的附件预览。工作台只构造固定图片 MIME 的 data URL；媒体页释放不再使用的 object URL。Markdown 不执行原始 HTML，媒体 Markdown 禁止远端图片和危险协议，不因展示文档而开放远端脚本或 iframe。

CSP 变更后，验证应用启动、页面导航与全部资源类型；出现白屏、图标缺失或字体加载失败时，检查控制台中的 CSP 拦截记录。

## 入参校验

前端传来的任何东西都不可信，即使是你自己写的界面。

现有 [`greet`](../src-tauri/src/commands.rs) 示范了 Rust 边界校验。应用自有数据使用固定目录与受控资源标识；用户外部文件由原生选择、拖入或关联参数授权，后续 IPC 接收 ID，不接受任意绝对路径。不要直接暴露整个临时目录、数据库路径或通用文件系统接口。

设置限制文档大小、层级与类型，使用 revision CAS；笔记限制标题 / 正文长度、ID 和版本范围，并参数化查询。同步存储与数据库操作由受控服务执行，命令不接受外部数据库路径或 SQL 字符串。新增命令须继续使用 `NativeError` 稳定错误码，详细内部错误只进脱敏日志。

访问已有文件时规范化根目录与目标，再按路径组件检查目标位于根目录中；同时考虑符号链接、检查与打开之间的竞态、文件大小和阻塞 I/O。简单字符串前缀检查不能建立文件访问边界。

[`workbench.rs`](../src-tauri/src/workbench.rs) 保存原生授权后的规范路径，拒绝普通链接 / 特殊文件，重开时核对原路径未被重定向；目录遍历不跟随链接，并检查规范路径仍在授权根内。读取有字节限制，文本必须为 UTF-8，图片限制格式并检查文件头；JSON / `.tdemo` 保存前校验。修改先写同目录临时文件，外部内容修订不一致则保留原文件并返回冲突。最后检查与系统替换之间仍有竞态窗口，该实现不是针对同一账户恶意并发进程的沙箱。

任务限制执行、排队、目录深度、文件数与哈希大小，合作取消不等于回滚，页面卸载不终止 Rust worker。文件关联和深链只处理指定后缀、scheme 及白名单路由；不得将传入参数作为命令行执行。固定 worker 仅启动当前应用的 `--demo-worker` 协议，用户文本通过参数数组传递，不提供可执行路径或 shell 字符串入口。

必查项：路径穿越（`..`）、空值、超长字符串、非法字符、数值范围。

**永远不要**把前端传来的字符串拼进 shell 命令。要用就传参数数组，不要拼字符串。

## 密钥与证书

- 代码签名证书、更新私钥、API Key 一律走环境变量或 CI Secrets。
- 仓库里不放真实 `.env`；[`.gitignore`](../.gitignore) 已忽略 `.env`、`.env.*`、`*.local` 和常见私钥 / 证书格式，只放行不含凭据的 `.env.example`。忽略规则不能保护已被 Git 跟踪的文件；误提交后须撤销或轮换凭据。
- 更新私钥生成后**离线备份两份**。丢失后无法继续为信任旧公钥的客户端签发更新；正常换钥需提前通过旧私钥签发带新公钥的过渡版本，或通过受控部署 / 手动安装迁移，不能只替换服务器端公钥。
- 日志里不打印令牌、路径中的用户名、完整请求体。

## 依赖审计

```bash
pnpm audit
pnpm outdated

cd src-tauri
cargo audit          # 需要先 cargo install cargo-audit
cargo tree -d        # 检查重复依赖
```

若当前镜像不提供 audit 端点，可临时指定官方源：`pnpm audit --registry https://registry.npmjs.org`。网络请求失败表示审计未完成，不能据此认定没有漏洞。

- 锁文件（`pnpm-lock.yaml`、`Cargo.lock`）必须提交，固定解析后的依赖版本；系统工具链和外部构建工具仍需另行控制。
- CI 每周一执行 npm 与 Rust 依赖的漏洞审计（`.github/workflows/audit.yml`），本节命令用于本地复查与修复验证。
- 新增依赖按 [开发指南](./development.md#新增依赖的评审标准) 的三条标准评估。
- 出现高危漏洞时优先升级；无法升级要记录原因与缓解措施。

[`pnpm-workspace.yaml`](../pnpm-workspace.yaml) 为 WDIO 的部分传递依赖设置 scoped overrides。调整或移除 override 时，检查上游版本范围、审计结果并运行真实 E2E；可安装和类型检查通过不能证明工具链运行兼容。

## 更新通道

- 运行时策略从 `app.config.json` 读取，可由配置目录 `deployment.json` 覆盖；不接受前端传入任意更新 URL。端点强制 HTTPS、无凭据 / fragment，下载客户端拒绝重定向到 HTTP。
- 公钥缺失时禁用更新且不联网。已配置时使用签名校验并验证被签版本，不接受版本漂移、无效签名或跳过校验。
- 更新仅使用 Tauri v2 原生包；Rust updater 禁用旧 ZIP 兼容特性。对最终安装包签名后不得再改字节，Windows Authenticode 与更新签名顺序见 [构建与发布](./build-release.md#自动更新)。
- 更新私钥只用于构建 / CI，绝不写入品牌配置、部署文件或诊断信息；公钥可以提交。

`deployment.json` 的 `updates` 整体替换随包策略，不逐字段合并；端点或公钥为空会禁用更新，文件过大、不可读或内容无效会报错，不能假定自动回退默认源。安装前会再次读取策略，变更后必须重新检查更新。

该部署文件没有独立签名，能写入它的账户也能替换更新端点和受信公钥。受控部署须限制配置目录写权限，并通过可信渠道分发、审查配置；更新包验签不能防御同一账户已被控制的场景。前端 CSP 不限制 Rust 发起的更新请求，下载仍由原生 HTTPS 与签名策略约束。

## 本地数据

| 数据        | 存放                                                                     | 要求                              |
| ----------- | ------------------------------------------------------------------------ | --------------------------------- |
| 用户偏好    | 原生 `appConfigDir/settings.json`；浏览器及原生首帧缓存使用 localStorage | 原子写、revision、不含敏感信息    |
| 业务数据    | `appDataDir` 下的 SQLite                                                 | 按用户隔离                        |
| 逻辑备份    | `appDataDir/backups`，或用户明确选择的 JSON 导出位置                     | 含完整笔记 / 草稿，按业务数据保护 |
| 文件 / 任务 | 用户授权文件与 `appDataDir/workbench` 历史 / 报告                        | 不将路径授权等同于磁盘隔离        |
| 令牌、密码  | 系统凭据服务，Rust `keyring` 的应用专用演示项                            | 不落明文                          |
| 临时文件    | 需要时在 `appCacheDir` 下按任务隔离                                      | 由创建方定义并执行清理时机        |

当前偏好、SQLite 笔记、备份、工作台历史 / 报告及日志均未加密；按用户存放不等于加密或隔离同一账户下的其他进程。凭据演示通过 keyring 增读删应用标识下的固定项，E2E 构建禁用；读取后会进入当前界面内存，系统凭据服务不可用时明确报错。它不实现 OAuth、远程会话或自动令牌刷新；本地限时会话示例不存真实令牌。

「重置偏好」恢复外观、布局和应用后台偏好，保留语言，不删除笔记、日志、窗口存档、WebView 数据，也不修改系统自启动项。前端设置同步遇到未来 schema 会阻止自动写回；数据库未来 schema 由 Rust 拒绝修改。可读取且大小在限制内的无效设置会先备份再恢复；超出读取上限、读取失败或无法保留备份时，启动入口转入隔离恢复而不强行覆盖。用户数据清理需另设明确入口和范围。

备份为有格式 / schema 的全量逻辑 JSON，限制 16MiB，拒绝未知格式、非法标识、重复记录与超限内容。恢复前先保留当前完整备份，再在事务中替换；旧编辑版本不能覆盖恢复后的数据。启动恢复使用临时工作区，用户确认后仅暂存待恢复数据，下次启动以受控文件名、归档和日志完成替换；中断时回滚或保留恢复证据。未来版本拒写、事务备份和退出保存协商各有作用，均不能代替备份副本保管、磁盘故障演练或平台安装验收。

## 日志

- 生产构建默认不输出调试日志。
- 日志文件写在 `appLogDir`，单份上限 1 MB、保留 3 份历史归档及当前日志（`lib.rs` 显式配置，不依赖插件默认值），时间为本地时区。
- 提供给用户"导出诊断日志"时，先脱敏（路径、用户名、令牌）。
- 当前诊断预览只读取有限的近期日志，剥离 URL 凭据、query / fragment 以及常见秘密 / 用户主目录；前端异常记录有限流。复制和反馈前仍须人工复核，不把脱敏器当作所有业务数据的过滤保证。
