# 安全规范

本文说明 IPC、权限、更新和本地数据的安全边界。桌面代码运行在用户机器上，不应将随包配置或前端代码当作秘密存储。

## 攻击面

| 面               | 风险                             | 主要防线                                                                     |
| ---------------- | -------------------------------- | ---------------------------------------------------------------------------- |
| WebView 里的内容 | XSS → 拿到 IPC 调用能力          | CSP、不使用 `dangerouslySetInnerHTML`、外链隔离                              |
| IPC 命令         | 参数未校验导致路径穿越、命令注入 | Rust 侧校验入参                                                              |
| 能力声明         | 权限开太大，前端被攻破即失守     | capabilities 最小化                                                          |
| 依赖             | 供应链投毒                       | 锁文件、审计、来源审查                                                       |
| 更新通道         | 中间人替换安装包                 | 签名校验 + HTTPS                                                             |
| 本地数据         | 明文存储敏感信息                 | 系统钥匙串、按需加密                                                         |
| Wasm 扩展        | 第三方模块、数据交付和资源消耗   | Extism 限额、可终止 worker、可选授权、精确来源 broker、KV CAS 与系统凭据引用 |

## 能力最小化

`src-tauri/capabilities/` 中的声明是 Tauri 核心与插件命令的**白名单**，未授予的能力默认拒绝。

自定义 Rust 命令另有规则：本项目没有启用应用命令 ACL，`bindings.rs` 注册的命令默认可由本地应用前端调用。需要按窗口限制自定义命令时，先通过 `tauri_build::AppManifest::commands` 定义应用 ACL，再声明权限并分配到 capability。入参校验始终放在命令内部，生成 TypeScript 不替代运行时校验。

主 / 次窗口的权限列表以 [`default.json`](../src-tauri/capabilities/default.json) 为准，只分配给 `main` / `secondary`；扩展宿主窗口另用 [`extensions.json`](../src-tauri/capabilities/extensions.json)，两者均没有远程页面 capability。主 / 次窗口当前直接开放给前端的插件能力包括：

| 能力           | 范围与用途                                                                   |
| -------------- | ---------------------------------------------------------------------------- |
| 窗口及核心能力 | 标题栏、窗口显示和既有核心 API                                               |
| 通知           | 查询 / 请求系统授权、发送通知和接收点击；后台任务通知不主动弹授权请求        |
| 剪贴板         | 用户主动读取 / 写入文本，没有后台监听                                        |
| 全局快捷键     | 登记、检查和释放；门面再限制演示组合，插件 capability 本身不限制组合         |
| HTTP           | 仅 `httpbin.org` 与 `jsonplaceholder.typicode.com`，重定向目标继续检查 scope |
| opener         | `http(s)` URL 交给系统浏览器，不在可信 WebView 载入远程网页                  |

原生 dialog、目录定位、数据库、更新、凭据、自启动和固定 worker 由 Rust 服务调用；未向前端开放通用文件、任意 Shell、SQL 或 updater 插件命令。注册插件不等于授予其全部前端权限；Rust 服务直接使用插件的能力仍需在自定义命令内校验。窗口状态由 Rust 插件自动管理。自定义命令规则参考 [Tauri 应用命令权限](https://v2.tauri.app/security/capabilities/)。

扩展中心通过自定义 IPC 管理 Extism Wasm 包，仅增加专用 extension-ui frame 来源；独立窗口使用 `capabilities/extensions.json` 的有限宿主能力（事件、窗口、用户触发的剪贴板写入与外链），不开放直接文件 / HTTP 插件权限；Tauri bundle 资源仅增加第三方许可文件。授权确认属于本地可信前端流程，不抵御已被控制的 WebView；自定义命令仍需应用自身边界校验。Wasm 不获得本机目录、环境或系统命令。文件只按用户主动选择的资源交付；HTTP 效果按插件当前授权、精确来源及方法校验，可选网络能力被拒绝时不影响离线命令。命令所需能力是启动门槛，授权主体仍是整个插件，不构成按命令隔离。运行、资源与存档边界见 [扩展指南](./extensions.md)。

应用视图输入输出由 Rust 校验，宿主渲染有界字段、图表、分页表格、进度、内嵌栅格图片和安全 Markdown，通用视图不解释 HTML、脚本、远程图片或 CSS；需要自定义布局时使用独立的本地 UI 文档，不能将其注入主文档。安装身份另用 generation 区分，模块哈希相同不表示清单、来源或安装记录相同；安装 / 替换 / 回退更换 generation，启用 / 授权调整保留，原生 IPC 校验以拒绝旧身份的晚到管理请求。普通按钮不重新发送已选文件，但已获授权的插件可返回网络或 KV 效果；宿主生成 host / results，前端不能伪造效果回传；效果批次在执行前检查重复 ID、累积数量和回传空间，响应省略通过保留 ID 的明确收据表达，不等同于副作用回滚。产物只在用户选择保存位置后写出，文件名、类型、编码和大小需匹配。会话导入不执行插件、不授予权限、不恢复文件资源 ID。

扩展网络与前端 HTTP 插件 scope 分开：公网 HTTPS 要求精确来源 / 方法、全部 DNS 地址通过公网检查并固定连接；本机 HTTP 需独立 `network:local` 授权且仅允许精确环回来源。拒绝代理、重定向、Cookie 和插件自带凭据 / 连接控制头，不能由公开域名解析进入内网。系统 keyring 按应用、插件、来源和别名隔离秘密，只有匹配 origin 的 broker 可注入 Bearer 头；没有读取密钥的 IPC。插件私有 KV 使用独立命名空间、配额、revision CAS 和原子写入，损坏 / 未来存档拒写；卸载保留 KV，凭据删除失败则阻止卸载。

旧开发版扩展恢复须由用户确认，只归档严格识别的旧协议注册表及其包目录，核对原始摘要并拒绝活动租约、生命周期切换与目录链接；未来、损坏和未知结构继续只读。归档后不继承权限，不修改私有 KV、凭据、设置或笔记，流程见 [旧扩展恢复](./extensions.md#旧开发版告警与恢复)。

可选 HTML 界面独立运行于无同源权限的 sandbox frame，响应 CSP 禁用远程脚本、直接网络、子框、worker、弹窗与下载。专用资源协议逐次检查租约、窗口、安装代次、授权和哈希；原生 invoke_system 在顶层判断后才创建带密钥传输，避免 WebView2 的子框注入泄漏可用 IPC。SDK 在文档开始时锁定 WebRTC，主题和消息仅走有限桥。边界及剩余 UI 资源限制见 [自定义界面](./extensions.md#自定义界面)。上游传输适配源与许可见 [native-ipc.js](../src-tauri/src/native-ipc.js) 和 [许可](../resources/third-party/tauri.LICENSE)，升级 Tauri 时复核序列化、传输和平台注入行为。

执行采用固定自身可执行文件的无界面 worker，取消或时限覆盖编译、初始化与执行，父进程只管理自己创建的子进程；worker 仍以当前用户身份运行，进程分离不是额外的 OS 沙箱。WASI 不继承目录、环境或标准输出，直接 Extism HTTP 和系统命令仍关闭。完整调用的 60 秒预算通过合作取消实施，排队不计入；同步操作系统 I/O 无法硬性限时，租约保持到实际完成。停止等待不回滚已完成的网络 / 存储副作用。

官方市场的固定仓库和验证公钥来自应用配置，Rust 校验目录签名 / 有效期、GitHub HTTPS 与附件重定向、下载上限、完整包与模块哈希及清单一致性；最高 revision 与摘要跨重启持久化，拒绝旧目录和同 revision 替换，换源 / 公钥不复用旧缓存。市场安装重新核对来源收据，本地包不能伪造来源；受限可信 patch 可保留已有授权，其余更新及显式回退重新确认。签名不认证包内作者，不代替授权。当前线上旧目录尚未配套新协议发布，完整边界见 [官方插件市场](./extensions.md#官方插件市场)。

测试 WebDriver 仅由可选 `e2e` feature 编译，额外权限与全局 Tauri API 只放在测试 overlay；启动还要求独立 `.e2e` 标识及绝对临时数据目录。原生设置 / 数据库始终使用临时目录，Windows / Linux WebView 使用临时数据目录，macOS 测试 WebView 使用非持久 incognito 存储。正式配置不注册测试服务；隔离方式见 [真实桌面 E2E](./testing.md#真实桌面-e2e)。

规则：

- 一个权限一个理由。加之前先问：不加会怎样？能不能在 Rust 侧代劳？
- 不要用 `core:all` 或通配符图省事。
- 按窗口分配权限。如果以后加了「预览窗口」展示外部内容，它不应该有文件系统权限。
- 每季度复查一次，删掉不再需要的权限。

## CSP

生产规则在 [`tauri.conf.json > app.security`](../src-tauri/tauri.conf.json)，限制脚本、字体、图片与网络来源；新增资源来源时在同一提交调整并验证。

说明：

- `style-src 'unsafe-inline'` 是必需的：Radix 的浮层组件通过 `style` 属性做定位。
- `connect-src` 里保留 `ipc:` 与 `http://ipc.localhost`，否则 `invoke` 会被拦。
- `devCsp: null` 表示开发构建 **回退到生产 `csp`**（Tauri 源码 `AppManager::csp()`）。该规则用于 Tauri 提供的本地应用资源；Windows 的本地资源地址可能显示为 `http://tauri.localhost`，不能仅按 `tauri://` 字面判断。`pnpm app:dev` 则从 Vite dev server 加载外部 URL，开发时能加载资源不能证明正式包的 CSP 正确。
- 改成加载本地 `dist` 时应重新验证 CSP；构建产物本身不使用 Vite HMR。若另行接入开发资源，按实际地址配置 `devCsp`，不要预先放开固定 WebSocket 端口。
- 需要访问外部 API 时，在 `connect-src` 里精确列出域名，不要写 `*`。
- 宿主主文档当前只允许指定的两个 HTTPS 演示域名和 `wss://echo.websocket.events`；WSS 使用标准 WebSocket，门面检查协议、主机和消息大小。浏览器同源策略、桌面 CSP 与原生 HTTP 插件 scope 是不同边界，不能互相替代。
- 图片允许本地资源、`data:` / `blob:`，媒体仅允许本地和 `blob:`，用于用户明确选择的附件预览。工作台只构造固定图片 MIME 的 data URL；媒体页释放不再使用的 object URL。Markdown 不执行原始 HTML，媒体 Markdown 禁止远端图片和危险协议，不因展示文档而开放远端脚本或 iframe。

CSP 变更后，验证应用启动、页面导航与全部资源类型；出现白屏、图标缺失或字体加载失败时，检查控制台中的 CSP 拦截记录。

## 入参校验

前端传来的任何东西都不可信，即使是你自己写的界面。

现有 [`greet`](../src-tauri/src/commands.rs) 示范了 Rust 边界校验。应用自有数据使用固定目录与受控资源标识；用户外部文件由原生选择、拖入或关联参数授权，后续 IPC 接收 ID，不接受任意绝对路径。不要直接暴露整个临时目录、数据库路径或通用文件系统接口。

设置限制文档大小、层级与类型，使用 revision CAS；导入背景只保存本机重绘后的有界栅格 data URL，Rust 再验证格式、文件头、名称和体积，不接受路径、远端图片或 SVG。图库接口仅接收图片数据和内容 ID，存储路径由服务决定，版本与总量限制见 [ADR 0004](./adr/0004-wallpaper-library.md)。原生全屏能力分配给当前主 / 次窗口及可信扩展宿主窗口，CSP 和文件权限不扩展。笔记限制标题 / 正文长度、ID 和版本范围，并参数化查询。同步存储与数据库操作由受控服务执行，命令不接受外部数据库路径或 SQL 字符串。新增命令须继续使用 `NativeError` 稳定错误码，详细内部错误只进脱敏日志。

访问已有文件时规范化根目录与目标，再按路径组件检查目标位于根目录中；同时考虑符号链接、检查与打开之间的竞态、文件大小和阻塞 I/O。简单字符串前缀检查不能建立文件访问边界。

[`workbench.rs`](../src-tauri/src/workbench.rs) 保存原生授权后的规范路径，拒绝普通链接 / 特殊文件，重开时核对原路径未被重定向；目录遍历不跟随链接，并检查规范路径仍在授权根内。读取有字节限制，文本必须为 UTF-8，图片限制格式并检查文件头；JSON 与配置的应用专属扩展名文档保存前校验。修改先写同目录临时文件，外部内容修订不一致则保留原文件并返回冲突。最后检查与系统替换之间仍有竞态窗口，该实现不是针对同一账户恶意并发进程的沙箱。

任务限制执行、排队、目录深度、文件数与哈希大小，合作取消不等于回滚，页面卸载不终止 Rust worker。文件关联和深链只处理 [`app.config.json`](../app.config.json) 的 `integration` 所定义的后缀、scheme 及白名单路由；不得将传入参数作为命令行执行。派生配置与安装关联通过 [初始化流程](./development.md#项目初始化) 同步，不占用系统协议或通用文件扩展名。系统演示 worker 仅启动当前应用的 `--demo-worker`；扩展另用固定 `--extension-worker` 帧协议执行 Wasm，均不接受用户指定原生可执行路径或 Shell 字符串。

必查项：路径穿越（`..`）、空值、超长字符串、非法字符、数值范围。

**永远不要**把前端传来的字符串拼进 shell 命令。要用就传参数数组，不要拼字符串。

CSV 的解析、映射、校验、错误报告和完整导出均有界，文本字段导出时防公式解释；浏览器只主动下载，桌面保存通过现有原生选择与原子写入。差异结果只进入编辑器，不能替代磁盘 revision 或数据库版本检查。内容搜索仅使用笔记查询和已授权最近资源，不新增路径授权，范围见 [模块指南](./demo-modules.md#数据工作流与冲突比较)。

## 密钥与证书

- 代码签名证书、更新私钥、API Key 一律走环境变量或 CI Secrets。
- 仓库里不放真实 `.env`；[`.gitignore`](../.gitignore) 已忽略 `.env`、`.env.*`、`*.local` 和常见私钥 / 证书格式，只放行不含凭据的 `.env.example`。忽略规则不能保护已被 Git 跟踪的文件；误提交后须撤销或轮换凭据。
- 更新私钥生成后**离线备份两份**。丢失后无法继续为信任旧公钥的客户端签发更新；正常换钥需提前通过旧私钥签发带新公钥的过渡版本，或通过受控部署 / 手动安装迁移，不能只替换服务器端公钥。
- 日志里不打印令牌、路径中的用户名、完整请求体。

## 依赖审计

```bash
pnpm audit
pnpm outdated

cd src-tauri
cargo audit          # 需要先 cargo install cargo-audit
cargo tree -d        # 检查重复依赖
```

若当前镜像不提供 audit 端点，可临时指定官方源：`pnpm audit --registry https://registry.npmjs.org`。网络请求失败表示审计未完成，不能据此认定没有漏洞。

- 锁文件（`pnpm-lock.yaml`、`Cargo.lock`）必须提交，固定解析后的依赖版本；系统工具链和外部构建工具仍需另行控制。
- CI 每周一执行 npm 与 Rust 依赖的漏洞审计（`.github/workflows/audit.yml`），本节命令用于本地复查与修复验证。
- 新增依赖按 [开发指南](./development.md#新增依赖的评审标准) 的三条标准评估。
- 出现高危漏洞时优先升级；无法升级要记录原因与缓解措施。

[`pnpm-workspace.yaml`](../pnpm-workspace.yaml) 为 WDIO 的部分传递依赖设置 scoped overrides。调整或移除 override 时，检查上游版本范围、审计结果并运行真实 E2E；可安装和类型检查通过不能证明工具链运行兼容。

## 更新通道

- 运行时策略从 `app.config.json` 读取，可由配置目录 `deployment.json` 覆盖；不接受前端传入任意更新 URL。端点强制 HTTPS、无凭据 / fragment，下载客户端拒绝重定向到 HTTP。
- 端点或公钥缺失时禁用更新且不联网。已配置时使用签名校验并验证被签版本，不接受版本漂移、无效签名或跳过校验。派生项目初始化会清除不再适用的模板更新源与信任，显式配置后的实际策略仍需核对；具体触发规则见 [初始化流程](./development.md#项目初始化)。
- 启动检查由主窗口在设置就绪后发起，可通过 `autoCheckUpdates` 关闭；检查失败不弹窗，后台提醒只引导查看，下载 / 安装须用户确认。检查与下载的超时边界见 [自动更新](./build-release.md#自动更新)。
- 更新仅使用 Tauri v2 原生包；Rust updater 禁用旧 ZIP 兼容特性。对最终安装包签名后不得再改字节，Windows Authenticode 与更新签名顺序见 [构建与发布](./build-release.md#自动更新)。
- 更新私钥只用于构建 / CI，绝不写入品牌配置、部署文件或诊断信息；公钥可以提交。

`deployment.json` 的 `updates` 整体替换随包策略，不逐字段合并；端点或公钥为空会禁用更新，文件过大、不可读或内容无效会报错，不能假定自动回退默认源。安装前会再次读取策略，变更后必须重新检查更新。

该部署文件没有独立签名，能写入它的账户也能替换更新端点和受信公钥。受控部署须限制配置目录写权限，并通过可信渠道分发、审查配置；更新包验签不能防御同一账户已被控制的场景。前端 CSP 不限制 Rust 发起的更新请求，下载仍由原生 HTTPS 与签名策略约束。

## 本地数据

各数据的位置、持久化与备份范围统一见 [数据存储](./architecture.md#数据存储)。偏好须保留原子写入与 revision，且不含敏感信息；逻辑备份包含完整笔记 / 草稿，导出后仍按业务数据保护。外部文件授权不等于磁盘隔离。临时文件按任务在 `appCacheDir` 隔离，由创建方定义并执行清理时机。

当前偏好、SQLite 笔记、备份、工作台历史 / 报告及日志均未加密；按用户存放不等于加密或隔离同一账户下的其他进程。凭据演示通过 keyring 增读删应用标识下的固定项，E2E 构建禁用；读取后会进入当前界面内存，系统凭据服务不可用时明确报错。它不实现 OAuth、远程会话或自动令牌刷新；本地限时会话示例不存真实令牌。

重置偏好按 [设置迁移](./architecture.md#状态管理与设置迁移) 的范围执行，用户数据清理需另设明确入口和范围。设置与数据库遇到未来 schema 均须拒绝自动覆盖；读取、备份或迁移失败时保留原件，按 [恢复流程](./architecture.md#恢复诊断与更新) 隔离故障，不通过删除用户数据修复。

备份导入在 Rust 边界拒绝未知格式、非法标识、重复记录与超限内容；恢复必须先保存完整安全备份，再事务替换并使旧编辑版本失效。启动替换须由用户确认，使用受控文件名、归档与恢复日志，中断时回滚或保留证据。未来版本拒写、事务备份和退出保存协商均不能代替备份副本保管、磁盘故障演练或平台安装验收。

## 日志

- 生产构建默认不输出调试日志。
- 日志目录、轮换与时间戳见 [日志排障](./troubleshooting.md#先看日志)，不在多处维护同一组配置数值。
- 提供给用户"导出诊断日志"时，先脱敏（路径、用户名、令牌）。
- 当前诊断预览只读取有限的近期日志，剥离 URL 凭据、query / fragment 以及常见秘密 / 用户主目录；前端异常记录有限流。复制和反馈前仍须人工复核，不把脱敏器当作所有业务数据的过滤保证。

## 漏洞上报

见根目录 [SECURITY.md](../SECURITY.md)。内部发现的漏洞先走私密渠道，不要开公开 issue。

插件自定义界面使用独立响应 CSP 和无同源权限的内容框，不能把内容注入宿主 DOM。资源、端口、预算与撤权规则统一见 [自定义界面](./extensions.md#自定义界面)。UI 租约使用 getrandom 取得操作系统随机数；该 MIT / Apache-2.0 小型库已在现有依赖树中，本次显式使用，不增加前端包体，支持现有桌面目标。
