# 扩展界面 SDK

协议、资源和权限的权威说明见 [扩展指南](../docs/extensions.md#自定义界面)。`extension-ui.js` 由宿主注入隔离的内容框，插件无需复制或远程加载它；`extension-ui.d.ts` 提供作者编辑器类型，视图 DTO 引用生成绑定。

SDK 脚本由 Rust 在编译时嵌入并于文档开始时注入；修改 SDK 后需重新构建并重启桌面进程，前端 HMR 不会替换已运行进程中的注入脚本。默认 CSS 内嵌在 SDK 中，插件不应另外加载一份 SDK 或依赖内部主题控制消息。

清单的视图命令声明 `ui.document: "main"`，将自包含的 HTML 放在 `ui/main.html`，CSS、JavaScript 和图片内嵌。可以用普通 DOM，也可由自己的框架构建为单文件。打包时传入 `--ui-dir <目录>`；文档引用、大小和完整性由原生工具核验。

```html
<button id="refresh" type="button">刷新</button>
<pre id="result"></pre>
<script>
  starter.onChange(({ view, busy }) => {
    document
      .querySelector("#refresh")
      .setAttribute("aria-disabled", String(busy));
    document.querySelector("#result").textContent = view?.display ?? "";
  });
  document.querySelector("#refresh").onclick = async () => {
    try {
      await starter.run("refresh");
    } catch {
      await starter.notify("刷新失败，请重试。", { tone: "error" });
    }
  };
</script>
```

`ready` 完成首次连接，`onChange` 订阅视图、当前字段、语言、主题 token、授权和忙碌状态。`run(action, fields)` 合并当前视图已声明字段后调用本命令的 Wasm 函数；`setFields` 只更新当前窗口中的输入，不执行 Wasm。首个快照到达前收到关闭通知或发生消息解码错误时，`ready` 和等待连接的调用会拒绝；这些事件也会拒绝已连接的未完成请求。消息发送失败会拒绝对应调用。操作失败应保留输入并给用户可理解的反馈。

`notify(message, { tone })` 在宿主右下角显示与应用一致的临时消息，不占用插件内容区，也不会推挤布局；这是宿主 toast，不是操作系统通知。`tone` 可选 `info`（默认）、`success`、`error`；文本须非空、不含 NUL，UTF-8 长度最多 2 KiB。宿主仅渲染纯文本，并标明插件名；同一会话的新提示替换上一条。成功提示应在真实操作确认后发送，失败提示按 `code` 映射到当前语言，不直接显示桥接诊断文本。常驻说明、字段校验、重试入口和长文布局遵循 [说明与布局稳定](../docs/conventions/ui-guidelines.md#说明与布局稳定)，只在业务确有需要时占用内容区。

隔离文档不开放表单提交；自定义交互使用 `type="button"` 的 click 与显式键盘事件调用 SDK，不依赖表单默认 submit、`requestSubmit()` 或 `onsubmit` 才阻止导航。

宿主语言变化时会立即发送新 `locale`，同时更新文档 `lang`。作者应在 `onChange` 中按 `locale` 重绘自己的固定文案，不用重新载入页面。Wasm 视图使用 `action: null` 携带已有 state / fields 重新渲染；插件应将这种请求视为纯渲染，不清空会话或触发业务写入。宿主等待当前动作结束再刷新，并保留字段草稿和检查点；新语言不会使正在运行的业务请求取消或重试。

## 默认外观与动效

SDK 自动注入 `starter-defaults` CSS layer，提供与宿主一致的 2rem 默认按钮 / 输入高度、字体、字号、语义色、圆角、焦点、禁用反馈和 8px 细滚动条。表格、图片与文本也有基础样式，页面默认内边距为 1rem。所有普通作者 CSS 都优先于该 layer；可以直接改变组件的字号、尺寸、颜色和布局，无需 `!important`，也无需复制宿主组件库。

隔离内容框占满侧栏右侧或独立窗口标题栏下的可用宽度，贴齐主内容右边缘，文档滚动条位于内容区最右侧；高度按外壳实际剩余空间计算。宿主不再为内容框叠加阅读宽度和外层内边距。文档与业务容器按内容自然排版，以文档承担整页滚动，避免再给搜索结果、表单等普通区块设置固定高度和独立滚动；默认 body 不用视口最小高度叠加内边距撑出第二条滚动条。需要居中排版时，在文档内部的 `main` 等容器设置 `max-width`、自动外边距和 padding，保留整个文档作为页面滚动区域。

普通单选 `select` 默认渐进增强为使用主题 token 和圆角的下拉弹层，原来的 DOM 节点仍是值与表单状态的来源。保留 `value`、`selectedIndex`、表单关联 / reset、`input` / `change` 事件、fieldset 禁用和 optgroup 语义，不改写原型或要求作者迁移事件处理。`multiple`、`size > 1` 和 `data-starter-select="native"` 保留原生交互；作者可用最后一个属性明确退出增强。普通作者 CSS 仍优先于默认样式层，增强不额外开放表单提交权限。

`theme.tokens` 提供背景、前景、卡片、弹层、主要 / 次要 / 强调 / 危险交互、边框、输入、焦点、图表与圆角变量，以及 `--host-font-family` / `--host-font-size`。Geist 的本地字体通过 data 字体提供给隔离文档；系统字体沿用宿主栈，不需要插件发起字体网络请求。普通正文、控件和状态文字继承应用字体，代码与结构化原始输出才按需要使用等宽字体。令牌随跨窗口设置同步更新，SDK 不另存一份主题或语言偏好。

`theme.mode` 为 `light` / `dark`，对应根元素的同名 class；`theme.motion` 为 `full` / `reduced`，对应根元素 `data-motion`。SDK 同时遵循系统减少动效设置。作者自己的持续动画仍应在离屏、隐藏、卸载和 reduced motion 时停止；不要仅依靠 CSS 缩短动画时长来运行后台循环。

从宿主切换主题时，隔离内容框会在自己的文档中同步捕获旧画面，以同一圆心、半径、时间和 easing 展开圆形 View Transition。跨源隔离保持不变；不支持 API、用户减少动效、过渡跳过或窗口隐藏时直接应用新主题，不影响输入和操作结果。

首次显示前，宿主按真实加载状态显示骨架，内容框保持可测量。SDK 在收到首个非空 view、应用首轮主题且 DOM 就绪后，等待两次动画帧机会再通过内部握手通知宿主展示；这不是新增作者 API，不应手工发送内部消息。`ready` 表示连接和首个快照可用，不表示作者自己的异步业务已经完成；需要异步数据时仍由插件显示真实加载与失败状态。骨架不人为延长，后续忙碌不会重新隐藏已经展示的内容框。

首屏呈现握手停滞时，宿主显示可重试错误；文档后台或内容框离屏时不按前台等待误报。这只确认主题和渲染机会，不证明作者业务渲染成功，也不替代插件自己的错误处理。它与业务 RPC 不同，不为所有服务调用添加统一前端超时。

`checkpoint(value, dirty)` 保存最多 256 KiB 的 JSON 草稿，并明确报告未保存状态；不要只把输入保存在 iframe 的局部变量里。宿主暂离后重建界面时，从快照的 `checkpoint` 恢复。完成插件自己的业务保存后可报告 `dirty: false`；宿主通用“保存”导出会话 JSON，包含检查点，并不冒充插件业务保存。导入绑定文档哈希及原有插件身份，不自动执行代码或恢复文件授权。

`saveArtifact(index)` 请求保存当前视图已生成的产物，用户仍在系统对话框中选择路径，取消时返回 `false`。不存在任意路径写入、任意 IPC、凭据读取或绕过权限的通道。SDK 使用原生文档启动脚本，无需在 HTML 引用它，不改变正常 HTML / 模块的解析语义。原生 IPC 的密钥传输仅安装到顶层宿主；CSP 与 WebRTC 启动限制共同约束未声明网络。普通 HTML 链接跳转、直接网络、弹窗、直接下载、跨框 DOM 与浏览器存储仍受隔离约束；通用 HTTP / KV 使用 Wasm 受控效果，安全外链及其他固定能力使用下述服务。

## 注册的宿主服务

`starter.services.request(service, request)` 调用已经注册的 `lan`、`wallpaper`、`resources` 或 `links` 服务，不会自动执行 Wasm，也不会把状态查询冒充成整个插件忙碌；需要的界面工作状态由作者按该请求维护。`extension-ui.d.ts` 为图片资源和外链提供具体返回类型，`lan` / `wallpaper` 仍返回需要收窄的 `unknown`。类型不能代替宿主运行时校验；每次服务请求复核当前安装身份和独立授权，不接受界面提供原生路径、安装代次或任意 IPC 名称。能力矩阵、精确请求和额度统一见 [扩展指南](../docs/extensions.md#受控桌面服务)。

| 服务        | 所需权限                                                   | 作者调用                                                                                                 |
| ----------- | ---------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| `resources` | `network:images`；`system` 模式另需 `network:system-proxy` | `fetch-image` 传 `url` 与可选 `networkMode`；`preview` / `save` / `release` 使用返回的 `resourceId`      |
| `wallpaper` | `wallpapers:manage`；资源导入另需 `network:images`         | `list`、本机 `import`、`import-resource`、`apply`、`rename`、`remove`、`open-settings`，不提供供应商搜索 |
| `links`     | `links:open`                                               | `{ url }` 请求安全打开 HTTPS 来源页，成功返回 `null`                                                     |
| `lan`       | `messaging:lan`                                            | 手动连接和有限文本服务，不是通用后台执行接口                                                             |

`resources` 请求使用 `action` 区分动作。`fetch-image` 返回 `{ resourceId, mime, bytes, width, height, sha256 }`；`preview` 返回 `{ dataUrl }`，可作为图片的本地展示内容；`save` 可附带安全文件名 `name`，由系统对话框决定路径，返回 `cancelled` 与成功时的文件名；`release` 返回 `null`。文件名是受限建议，不是路径；省略时宿主生成合适名称。另存保留已验证原图，`wallpaper` 的 `{ action: "import-resource", resourceId, name }` 则重绘压缩后加入现有图库，两者不能混淆。

资源 ID 绑定当前插件安装和原生窗口，具有 TTL 与配额；及时 `release` 不再使用的资源，过期、关闭、撤权或重启后重新取得，不把它存进会话当作持久下载资格。`release` 撤销后续查找，不取消已经取得资源并进入保存等在途操作；原生持有字节到真实操作结束，关窗仍等待活动并在最终提交拒绝旧窗口写入。图库预览繁忙或损坏时可以返回 `dataUrl: null`，调用方应保留真实列表 / 写入结果，不能把缺少缩略图当作写入失败。宿主会验证 MIME、实际解码、下载 / 像素 / 内存额度和生命周期。`network:images` 明确允许任意公网 HTTPS GET 图片来源，URL 查询也可能向原站发送数据；宿主不再证明它来自 Bing 或其他供应商。来源、许可和搜索响应解析由插件负责，不能用“图片权限”掩盖这一授权范围。

搜索在插件 Wasm 中通过已授权 HTTP 效果进行，仍需声明精确 origin 和方法；界面不能直接 `fetch` 原站。文本 HTTP 和图片的 `networkMode` 默认 `direct`；显式 `system` 要求代理权限，使用用户系统 / 环境代理及 `NO_PROXY`，不能由插件指定代理 URL 或关闭 TLS。本机 HTTP 不接受系统代理。代理远端解析目标时宿主不能证明最终公网 IP；直接传输仍核验并固定 DNS，来源、方法与内容预算保持生效。网络能力可声明为可选，缺少搜索、图片或外链授权不应阻塞本机图库。

后台状态读取应与用户操作分别管理在途状态，避免每轮查询都禁用输入、发送或连接按钮，也不要用旧快照覆盖等待期间的新草稿。手动操作结束后，忽略早于该操作发出的过期查询结果；保留焦点、选区和正在编辑的值。不要把静默轮询等同于业务提交。

服务请求与 `run` / 检查点等使用同一个受限通道：合计最多 4 项在途，消息大小与频率限制仍适用。失败 Promise 的 `code` 与 `retryable` 为稳定的结构化诊断；请按自己的语言显示反馈，不解析错误文本。原生再次校验启用、授权、模块哈希、安装代次和窗口令牌，读写门闩等待已开始的请求结束后再完成撤权或替换。ServicePermit 全程计入原生活动，关闭、退出、重启与更新等待真实操作结束，关闭后拒绝最终提交，窗口 epoch 隔离旧资源清理；服务调用不具备自动回滚语义。

SDK 不用统一的前端定时器截断全部请求：原生导入 / 保存对话框可以等待用户选择，完成后返回实际回执，界面关闭时通道失效。Wasm 和原生网络仍有各自预算；停止前端等待不能冒充原生取消，更不能报告尚未确认的写入成功或失败。

显式启动的 LAN 监听和接收属于原生服务；同一原生窗口切换页面或 iframe 重建不等于停止连接，最后一个使用窗口关闭、撤权、换安装身份或应用退出时才回收。多个窗口共享服务时，明确停止会影响其他窗口。不要为保持后台接收而保留隐藏 iframe，也不要让前端轮询冒充服务本身。LAN 为明文无账户的手动私有 IP 通信；系统剪贴板、操作系统通知和通用后台任务没有本轮调用者，尚未对插件开放。媒体能力要求配套 0.1.6 宿主；开发态旧供应商动作不保留兼容，已有图库和设置数据保留。完整动作、数据位置和限制统一见 [受控桌面服务](../docs/extensions.md#受控桌面服务)。

消息大小、频率、在途调用和生命周期限制见扩展指南。界面应处理 `busy`、键盘、触控、减少动效和明暗主题；使用 `textContent` 或框架的文本节点处理外部字符串。真实 WebView 的隔离和平台交互必须另行验收，浏览器检查不代表已测全部桌面平台。
